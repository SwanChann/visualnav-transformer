## 3. P0：离线 Pareto 实验怎么做

### 3.1 目标

回答：

> Which inference configurations provide the best latency-quality trade-off for a frozen NoMaD-style policy?

### 3.2 输入数据

优先读这些 CSV/JSON：

```text
ddim_overall_summary.csv
ddim_case_records.csv
cfg_overall_summary.csv
cfg_case_records.csv
overall_summary.csv
case_records.csv
tts_overall_summary.csv
tts_case_records.csv
encoder_overall_summary.csv
encoder_case_records.csv
joint_overall_summary.csv
joint_case_records.csv
```

### 3.3 建议新增脚本

```text
scripts/analysis/ral_offline_pareto.py
```

脚本职责：

1. 读取 DDIM/CFG/TTS/encoder 结果。
2. 统一字段名和单位。
3. 计算 latency mean/p50/p90/p95。
4. 计算 inferred Hz。
5. 计算 quality proxy。
6. 找 Pareto frontier。
7. 输出 CSV、Markdown 表、LaTeX 表和 PDF/PNG 图。

建议命令：

```powershell
python scripts/analysis/ral_offline_pareto.py --results results --out 投稿冲刺/workspace/offline_pareto
```

如果脚本尚未实现，先用 notebook 或临时脚本也可以，但最终投稿前要保留可复现入口。

### 3.4 指标定义

基础指标：

```text
latency_mean_ms
latency_p50_ms
latency_p90_ms
latency_p95_ms
hz = 1000 / latency_mean_ms
```

质量 proxy：

```text
quality = w_progress * forward_progress
        - w_smooth * smoothness_cost
        - w_invalid * invalid_ratio
        + w_diversity * useful_diversity
```

如果某些原始字段不全，优先保持透明：

- 有什么报什么。
- 缺什么写 `NA`。
- 不要为了好看编合成指标。

### 3.5 输出

必须输出：

```text
投稿冲刺/workspace/offline_pareto/offline_pareto_unified.csv
投稿冲刺/workspace/offline_pareto/table_offline_pareto.md
投稿冲刺/workspace/offline_pareto/fig_offline_pareto.pdf
投稿冲刺/workspace/offline_pareto/budget_modes.md
```

预算模式：

| 模式 | 候选配置 | 论文用途 |
|---|---|---|
| Baseline | DDPM / original setting | 证明原始扩散采样延迟高。 |
| Fast | DDIM-2, CFG=0, TTS=1 | 高频控制，质量可能较低。 |
| Balanced | DDIM-2, CFG=0, TTS=8 | 默认推荐配置候选。 |
| Quality | DDIM-2, CFG=2, TTS=8/16 | 复杂场景候选，但要报告额外延迟。 |

## 10. 不做清单

为了首投质量，以下内容不做或不作为主线：

- 不新增 Lite3 真机采集。
- 不重训 NavDP/SIDP/CE-Nav/X-Nav 级别模型。
- 不把跨形态 zero-shot 写成贡献。
- 不实现复杂动态 budget controller。
- 不把 TTS 写成新算法。
- 不把 MuJoCo 结果说成真实世界性能。
- 不隐藏失败视频。
