## 3. P0：离线 Pareto 实验怎么做

### 3.1 目标

回答：

> Which inference configurations provide the best latency-quality trade-off for a frozen NoMaD-style policy?

### 3.2 输入数据

优先读这些 CSV/JSON：

```text

```

### 3.3 建议新增脚本

```text
scripts/analysis/ral_offline_pareto.py
```

脚本职责：

1. 读取 DDIM/CFG/TTS/encoder 结果。
2. 统一字段名和单位。
3. 计算 latency mean/p50/p90/p95。
4. 计算 inferred Hz。
5. 计算 quality proxy。
6. 找 Pareto frontier。
7. 输出 CSV、Markdown 表、LaTeX 表和 PDF/PNG 图。

建议命令：

```powershell
python scripts/analysis/ral_offline_pareto.py --results results --out 投稿冲刺/workspace/offline_pareto
```

如果脚本尚未实现，先用 notebook 或临时脚本也可以，但最终投稿前要保留可复现入口。

### 3.4 指标定义

基础指标：

```text
latency_mean_ms
latency_p50_ms
latency_p90_ms
latency_p95_ms
hz = 1000 / latency_mean_ms
```

质量 proxy：

```text
quality = w_progress * forward_progress
        - w_smooth * smoothness_cost
        - w_invalid * invalid_ratio
        + w_diversity * useful_diversity
```

如果某些原始字段不全，优先保持透明：

- 有什么报什么。
- 缺什么写 `NA`。
- 不要为了好看编合成指标。

### 3.5 输出

必须输出：

```text
投稿冲刺/workspace/offline_pareto/offline_pareto_unified.csv
投稿冲刺/workspace/offline_pareto/table_offline_pareto.md
投稿冲刺/workspace/offline_pareto/fig_offline_pareto.pdf
投稿冲刺/workspace/offline_pareto/budget_modes.md
```

预算模式：

| 模式 | 候选配置 | 论文用途 |
|---|---|---|
| Baseline | DDPM / original setting | 证明原始扩散采样延迟高。 |
| Fast | DDIM-2, CFG=0, TTS=1 | 高频控制，质量可能较低。 |
| Balanced | DDIM-2, CFG=0, TTS=8 | 默认推荐配置候选。 |
| Quality | DDIM-2, CFG=2, TTS=8/16 | 复杂场景候选，但要报告额外延迟。 |

## 12. 2026-07-09 离线补强包

本节是基于当前结果资产和后续前沿调研后新增的 RA-L 补强方案。结论是：**当前工作黄灯可投，但必须把离线证据整理成主结果，而不是把 DDIM/CFG/TTS/encoder 分散成几张本科论文式消融图。**

### 12.1 目标

回答一个更像 RA-L 审稿问题的问题：

> Under a fixed NoMaD-style diffusion navigation policy, which inference configurations are worth their latency cost on a resource-constrained quadruped deployment?

这句话比“哪个参数最好”更稳，因为它把本文从调参报告提升为 deployment-time evidence。

### 12.5 质量代理

正文主图可以用一个质量代理，但表格必须同时保留分项。建议：

```text
quality_proxy =
    z(forward_progress)
  - z(smoothness)
  - z(lateral_abs)
  + 0.5 * z(useful_diversity)
  - z(invalid_or_saturation)
```

注意：

- `invalid_or_saturation` 缺失时不参与该配置的 proxy，必须在 notes 中说明。
- diversity 不能简单理解为越大越好；如果 endpoint drift 或 lateral drift 变差，要在 Discussion 里说明。
- 不要只按 `rank_score` 写结论，必须展示 latency 与分项指标。

### 12.6 Fig. 2 应该怎么画

主图建议三联：

1. x 轴 latency mean 或 p95，y 轴 quality proxy，标出 Pareto frontier。
2. 同一张图用颜色区分 DDIM / CFG / TTS / encoder / joint。
3. 右侧小图画 TTS budget 的边际收益：`TTS=0/8/16/32` 对 latency 与 forward progress 的影响。

图中必须标注四类 deployment modes：

| 模式 | 作用 | 候选配置 |
|---|---|---|
| Baseline | 原始扩散参考 | DDPM / DDIM-10 |
| Fast | 控制频率优先 | DDIM-1/2, CFG=0, TTS=0/1 |
| Balanced | 默认推荐 | DDIM-2, CFG=0, TTS=8 或 Pareto 等价配置 |
| Quality | 复杂场景候选 | DDIM-2, CFG=1/2, TTS=8/16 |

不要在图中暗示某个配置“全局最优”；只能说它在特定 latency budget 下更合理。

### 12.7 Table II 应该怎么写

Table II 不要塞满所有 65 个 TTS 配置，只放代表性配置：

| 类别 | 数量 | 目的 |
|---|---:|---|
| Baseline | 1-2 | 说明原始采样成本 |
| Fast | 2-3 | 说明低 latency 可达 |
| Balanced | 2-3 | 作为默认部署建议 |
| Quality | 2-3 | 展示质量提升和额外延迟 |
| Negative / dominated | 1-2 | 展示为什么大 budget 或过强 CFG 不值得 |

正文把完整表放 supplementary 或 workspace，不要让 RA-L 正文被大表拖垮。

### 12.8 和 MuJoCo 的连接方式

离线推荐配置必须映射到 MuJoCo：

```text
Fast -> one DDIM-2 low-budget config
Balanced -> one DDIM-2 + moderate TTS / equivalent config
Quality -> one higher budget config if existing MuJoCo data supports it
```

如果 MuJoCo 现有结果没有 TTS 维度，就诚实写：

> MuJoCo validates the closed-loop executability of representative DDIM/CFG/encoder configurations. TTS is evaluated offline as a candidate-budget analysis and left for closed-loop ranking in future work.

这样比硬把 TTS 说成闭环提升更安全。

### 12.9 不能塞进当前 RA-L 的内容

这些可以写在 Discussion / Future Work，但不要作为本篇 contribution：

- learned ranker / verifier。
- few-step / consistency distillation。
- navigation brain / world-action model。
- RL / preference fine-tuning。
- VLM high-level brain。

原因：它们会把当前 fixed-policy deployment analysis 改成新算法论文，需要新的闭环实验和更强 baseline。当前首投应该先把已有工作救成一篇短、硬、诚实的 RA-L。

### 12.10 若离线补强失败的决策

如果出现以下情况，就不要硬投：

- 统一 Pareto 图无法形成清楚趋势。
- Table II 只能说明“某一次配置好”，不能说明 latency-quality trade-off。
- MuJoCo 无法对应离线推荐配置。
- 真机材料无法完成人工 outcome 标注。
