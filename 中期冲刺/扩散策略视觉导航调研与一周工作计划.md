## 一、扩散策略在通用视觉导航的最新开源工作

### 1.1 技术演进路线

GNM (2022) → ViNT (2023) → NoMaD (2023) → NavDP / NaVILA / CAST (2025)

核心演进逻辑：从「单数据集单机器人」到「多数据集跨机器人」，从「确定性策略」到「扩散策略 / VLA大模型策略」。

### 1.2 重点开源项目

#### (1) NoMaD / ViNT / GNM — 原始仓库（本项目）
- GitHub: https://github.com/robodhruv/visualnav-transformer
- 论文: NoMaD: Goal Masked Diffusion Policies for Navigation and Exploration (2023), ICRA 2024 Best Paper
- Stars: ~1.2k
- 描述: 扩散策略视觉导航的奠基工作。使用 EfficientNet-B0 + Transformer 编码视觉特征，DDPM 生成 waypoint 轨迹，Goal Masking 统一导航与探索。模型轻量（参数量约 50M），单卡 4090 可训练。
- 动作空间: 8 个 (x,y) waypoint，相对坐标系
- 状态: 稳定，不再频繁更新

#### (2) InternNav — NavDP (Navigation Diffusion Policy)
- GitHub: https://github.com/InternRobotics/InternNav
- 论文: NavDP: Learning Sim-to-Real Navigation Diffusion Policy (IROS 2025)
- Stars: ~740，活跃更新（2025年3月仍有提交）
- 描述: NoMaD 的直接后继者。核心改进包括：(a) 引入仿真预训练 + 真实微调的 Sim2Real 流程；(b) 使用更强的视觉编码器（CLIP/DINOv2）替换 EfficientNet；(c) 提出 InternVLA-N1 大模型导航智能体，支持语言指令。
- 关键: 已在 Unitree Go2（四足）和 G1（双足人形）上部署验证
- 动作空间: 离散动作（前进、左转、右转、停止）
- 与NoMaD区别: 动作空间从连续 waypoint 变为离散指令，视觉编码器更强，支持语言条件

#### (3) NaVILA — 足式机器人视觉导航
- GitHub: https://github.com/AnjieCheng/NaVILA
- 论文: NaVILA: Legged Robot Vision-Language-Action Model for Navigation (RSS 2025)
- Stars: ~556
- 描述: 专为足式机器人设计的 VLA（Vision-Language-Action）导航模型。使用大语言模型作为策略骨干，支持语言指令导航。
- 关键: 已在 Unitree Go2（四足）、G1/H1（双足）、Booster T1（轮式双足）上实机验证
- 动作空间: 离散导航动作 + 独立的运动控制策略
- 与NoMaD区别: 用 VLA 大模型替代扩散策略，但导航思路一致（高层规划 + 低层运动解耦）

#### (4) Diffusion Policy — 底层依赖
- GitHub: https://github.com/real-stanford/diffusion_policy
- 论文: Diffusion Policy: Visuomotor Policy Learning via Action Diffusion (RSS 2023)
- Stars: ~3.9k
- 描述: NoMaD 扩散策略部分的理论基础。主要用于机械臂操作任务，但其 Conditional UNet1D 架构被 NoMaD 直接复用。
- 与NoMaD关系: NoMaD 的噪声预测网络直接来自此项目

#### (5) CityWalker — 从网络视频学城市导航
- GitHub: https://github.com/ai4ce/CityWalker
- 论文: CityWalker: Learning Embodied Urban Navigation from Web-Scale Videos (CVPR 2025)
- Stars: ~202
- 描述: 利用互联网城市行走视频（如 YouTube 步行视频）训练导航策略，无需机器人数据采集。支持四足机器人部署。
- 创新点: 数据来源从机器人自采集扩展到海量网络视频
- 与NoMaD区别: 数据源不同，不需要机器人数据采集过程

#### (6) CAST — NoMaD 作者后续工作
- GitHub: https://github.com/catglossop/CAST
- 论文: Commonsense Affordance-based Subgoal Transition (2025)
- Stars: ~32
- 描述: NoMaD 共同作者 Catherine Glossop 的后续工作。在 NoMaD 基础上引入常识推理和可供性（affordance）分析，用于更智能的子目标选择。
- 与NoMaD关系: 在 NoMaD 的 topomap 导航之上增加语义理解层

## 二、通用视觉导航与机器人形态的关系

### 2.1 核心结论：导航策略可跨形态泛化，但需要分层解耦

GNM (Shah et al., 2022) 的实验首次证明：一个在多种机器人数据上训练的导航模型，可以在从未见过的机器人上零样本工作（包括四旋翼）。关键在于「归一化动作空间」——将不同机器人的动作统一为归一化后的 waypoint 位移。

这意味着视觉导航存在一个与形态无关的抽象层：

    "Where to Walk"（去哪里）→ 形态无关，可共享
    "How to Walk"（怎么走）→ 形态专用，需独立控制器

### 2.2 三种跨形态接口范式

(1) Waypoint 接口（GNM / ViNT / NoMaD 采用）
- 导航策略输出 (dx, dy) 相对位移
- 通过 PD 控制器转换为 (v, ω) 速度指令
- 对接足式机器人：速度指令 → 步态控制器 → 关节命令
- 优点：最通用，形态完全解耦
- 缺点：不感知地形，不适应复杂路面

(2) 离散动作接口（NaVILA / InternNav 采用）
- 导航策略输出离散动作（前进、左转、右转、停止）
- 每个动作对应一段运动控制器执行
- 优点：简单可靠，易于部署
- 缺点：动作粒度粗，缺乏精细控制

(3) 速度指令接口（VP-Nav 采用）
- 导航策略直接输出 (v_x, v_y, ω) 速度指令
- 对接 RL 训练的运动控制策略
- 优点：连续控制，较精细
- 缺点：需要运动控制策略配合

### 2.3 足式机器人部署的独特意义

为什么要在四足/双足上做视觉导航，而不只用轮式？

(1) 地形适应能力
- 四足机器人可翻越台阶、穿越草地、走不平路面
- 双足机器人可上下楼梯、穿越狭窄空间
- VP-Nav (CVPR 2022) 实验表明：四足在玻璃墙检测和冲击恢复上显著优于轮式

(2) 日常环境部署需求
- 人类生活环境为人类设计（楼梯、门槛、台阶）
- 轮式机器人在这些环境中寸步难行
- 足式机器人天然适应人类环境

(3) 本体感受的重要性
- NaVILA 的实验表明：引入本体感受信息（关节角度、力矩、IMU）的视觉运动策略，比纯盲运动策略的导航成功率显著更高
- 这意味着导航和运动之间存在有意义的信息流动，不是完全解耦的

(4) 研究空白——这是你的机会
- 目前开源项目中，扩散策略 + 足式机器人导航的直接结合几乎没有
- NoMaD 的扩散策略只在轮式平台验证
- NaVILA / InternNav 在足式上验证，但用的是 VLA/离散动作，不是扩散策略
- 将 NoMaD 的扩散策略适配到足式机器人，是一个有明确创新点的方向

### 2.4 NoMaD 适配足式机器人的技术路径

NoMaD 输出的 waypoint (dx, dy) 本质上是形态无关的。适配路径：

    NoMaD 扩散策略
        ↓ 输出 waypoint (dx, dy)
    PD 控制器（已有 pd_controller.py）
        ↓ 转换为 (v, ω) 速度指令
    足式运动控制策略（需要对接）
        ↓ 如 Unitree Go2 的 RL locomotion policy
    关节命令
        ↓ 发送到电机

关键：中间只需要替换「PD控制器输出 → 机器人执行」这一层。NoMaD 本身不需要任何修改。

## 三、基于 NoMaD 的优化思路与新方向

### 3.1 思路一：DDIM 加速采样（最容易，1-2天可完成）

NoMaD 使用 10 步 DDPM 采样。可以替换为 DDIM 采样，用更少的步数（如 3-5 步）达到相近质量，提升推理速度 2-3 倍。

改动点：仅需修改 navigate.py 中的 noise_scheduler 配置
- 将 DDPMScheduler 替换为 DDIMScheduler
- 调整 num_inference_steps
- 对比不同步数下的轨迹质量

### 3.2 思路二：更强的视觉编码器（中等难度，2-3天）

NoMaD 使用 EfficientNet-B0（参数量 5.3M），是 2019 年的模型。可以尝试：
- (a) 替换为 DINOv2-Small（参数量 21M）：自监督预训练，特征更鲁棒
- (b) 替换为 CLIP ViT-B/16（参数量 86M）：跨模态预训练，支持语言条件

NavDP 已验证 CLIP/DINOv2 在导航任务上的优越性。4090 上 DINOv2-Small 可以训练。

改动点：修改 nomad_vint.py 中的 obs_encoder 和 goal_encoder

### 3.3 思路三：Classifier-Free Guidance 增强目标导向性（中等难度，2-3天）

NoMaD 的 Goal Masking 已经天然支持 Classifier-Free Guidance（CFG）：
- 训练时 50% mask = 学习了无条件生成 + 有条件生成
- 推理时可以用 CFG 公式：noise_pred = (1+w) * cond_pred - w * uncond_pred
- w 越大，轨迹越朝向目标，但多样性降低

这个 NoMaD 原始代码中没有实现，但理论上直接可用。

改动点：修改 navigate.py 的推理循环，每步同时做 mask=0 和 mask=1 的预测，然后用 CFG 公式合成

### 3.4 思路四：足式机器人适配层（需要仿真环境，3-4天）

在 Isaac Gym 或 PyBullet 中搭建 Unitree Go2 仿真环境：
- NoMaD 输出 waypoint → PD 控制器 → (v, ω)
- 对接开源的四足运动控制策略（如 legged_gym 或 walk-these-ways）
- 在仿真中验证端到端闭环

### 3.5 思路五：复现 NavDP 的核心改进（3-5天）

从 InternNav 仓库中提取 NavDP 的核心改进并移植到 NoMaD：
- Sim2Real 预训练流程
- 更强的视觉编码器
- 评估指标体系

## 四、一周工作计划（单卡 4090）

### Day 1（周一）：环境搭建 + NoMaD 基线复现

上午：
- 配置 conda 环境，安装依赖（PyTorch 2.x + CUDA 12.x + diffusers）
- 下载预训练权重（官方提供 nomad.pth）
- 下载 go_stanford 数据集（约 5GB，已有部分）

下午：
- 用预训练权重跑通推理流程（不需要 ROS，写离线脚本）
- 可视化模型输出：输入图像对 → waypoint 轨迹 → 绘制在图上
- 记录基线指标：推理时间、轨迹质量（视觉检查）

产出：确认 NoMaD 推理流程跑通，有可视化结果

### Day 2（周二）：DDIM 加速采样实验

上午：
- 阅读 DDIM 论文核心推导（Song et al., 2021）
- 在 navigate.py 基础上编写离线评估脚本，支持切换 DDPM/DDIM
- 实现 DDIMScheduler 替换

下午：
- 对比实验：DDPM-10步 vs DDIM-10步 vs DDIM-5步 vs DDIM-3步
- 评估指标：推理时间、轨迹与 DDPM 基线的 MSE、视觉质量
- 整理实验结果，绘制对比图表

产出：DDIM 加速采样的量化对比报告

### Day 3（周三）：Classifier-Free Guidance 实验

上午：
- 实现 CFG 推理逻辑：每步扩散同时做 mask=0 和 mask=1 的前向传播
- CFG 公式：noise_final = (1 + guidance_scale) * noise_cond - guidance_scale * noise_uncond
- 测试 guidance_scale = 0.0, 0.5, 1.0, 2.0, 3.0

下午：
- 可视化不同 guidance_scale 下的轨迹差异
- 分析：guidance 越强 → 轨迹越目标导向 → 但可能过于激进
- 结合 Day 2 的 DDIM，测试 DDIM + CFG 的组合效果
- 整理实验结果

产出：CFG 增强的量化分析 + 最佳 guidance_scale 推荐

### Day 4（周四）：视觉编码器升级探索

上午：
- 从 HuggingFace 下载 DINOv2-Small 预训练权重
- 修改 nomad_vint.py，将 EfficientNet-B0 替换为 DINOv2-Small
- 处理维度适配（DINOv2 输出 384 维 → 需要线性投影到 256 维）

下午：
- 用 go_stanford 数据集做短期训练（10-20 epoch，4090 约 2-3 小时）
- 对比 EfficientNet-B0 vs DINOv2-Small 的特征质量
- 如果训练不收敛，尝试冻结 DINOv2 backbone 只训练投影层和扩散头
- 记录训练 loss 曲线

产出：DINOv2 编码器的初步可行性验证

### Day 5（周五）：足式机器人适配方案设计

上午：
- 安装 PyBullet，加载 Unitree Go2 URDF 模型
- 编写简单的速度指令控制接口：输入 (v, ω) → Go2 行走
- 可使用开源的 Go2 运动控制策略（如 legged_gym 的预训练权重）

下午：
- 将 NoMaD 的 PD 控制器输出对接到 PyBullet 仿真
- 实现闭环：固定目标图像 → NoMaD 推理 → waypoint → PD → (v,ω) → Go2 移动
- 如果时间不够，先做开环验证：给定一系列观察图像，输出对应的速度指令序列
- 记录仿真截图和视频

产出：NoMaD → 四足机器人的适配方案原型

### Day 6（周六）：整合实验 + 消融研究

上午：
- 整合 Day 2-4 的最佳配置：DDIM-5步 + CFG-1.0 + DINOv2（如果可用）
- 在完整测试集上跑评估
- 消融实验矩阵：
  - 基线 NoMaD (DDPM-10, EfficientNet, no CFG)
  - + DDIM-5
  - + CFG-1.0
  - + DDIM-5 + CFG-1.0
  - + DINOv2 (如果Day4成功)

下午：
- 整理所有实验数据，绘制对比表格和图表
- 分析各项改进的贡献
- 与 NavDP/NaVILA 论文中的报告指标做定性对比

产出：完整的消融实验报告

### Day 7（周日）：文档撰写 + 后续规划

上午：
- 撰写实验报告，包含：
  - 调研总结（本文档的精简版）
  - 实验设置和结果
  - 各项改进的量化分析
  - 足式适配方案的可行性分析

下午：
- 规划下一步工作：
  - 如果 DINOv2 有效 → 深入训练，扩展数据集
  - 如果 CFG 有效 → 探索自适应 guidance scale
  - 如果仿真验证通过 → 准备真机部署方案
- 整理代码，提交到 Git 仓库
- 撰写下周计划

产出：完整的项目报告 + 代码仓库 + 下阶段计划
