# 具身导航 Agent 方向、单卡 RTX 4090 与 Lite3 真机部署可行性调研

更新日期：2026-07-29

适用项目：`visualnav-transformer` / NoMaD-style Lite3 视觉导航 / TinyNavBrain 后续研究

决策状态：**CONDITIONAL-GO（有条件进入 Agent 方向）**

## 1. 先给出结论

### 结论一：这个项目适合朝具身导航 Agent 方向发展，但不能把现有导航策略直接替换成一个高频运行的大模型

推荐的变化不是“放弃 NoMaD，改用一个 7B 或 8B 大模型直接控制机器人”，而是：

> 把 NoMaD 或 TinyNavBrain 保留为快速、可回退的局部导航能力；在它上面增加低频、按事件触发的视觉语言决策 Agent，负责理解任务、选择子目标、调用导航能力、判断是否需要重规划，以及在失败时询问、回退或停止。

在这套结构里：

- NoMaD/TinyNavBrain 是快速执行局部 waypoint 的“小脑”或 `System 1`。
- 小型 VLM/Agent 是低频做语义决策的“大脑”或 `System 2`。
- 现有 waypoint-to-velocity adapter、安全桥和 Lite3 运动控制链继续保留。
- 大脑变慢、断网或输出过期时，机器人不能一直执行旧命令；只能执行有上限的一小段，然后停车或进入安全回退。

这一路线与 2024–2026 年 NaVILA、DualVLN、TIC-VLA、REAL 等工作的共同趋势一致：**大模型负责低频推理，轻量策略和传统控制负责快速闭环**。

但“慢大脑 + 快小脑”本身已经不是新贡献。尤其 TIC-VLA 已经使用 1B 视觉语言模型、0.5 Hz 大脑、10 Hz 动作策略，并显式建模 0–10 秒延迟和自运动偏移。因此，若本项目只是给 TinyNavBrain 外面套一个 VLM，就不够形成 2026 年的论文创新。

### 结论二：单张 RTX 4090 可以支撑这条路线的研究原型，但不能支撑所有规模和所有训练方式

分层判断如下：

| 工作 | 当前判断 | 含义 |
|---|---|---|
| 训练和部署 8.5M 参数量级的 TinyNavBrain | **GO** | 项目已有 200-step 管线测试和低显存收据；仍未证明模型效果 |
| 训练约 450M 的轻量 VLA/Agent | **CONDITIONAL-GO** | 单卡有可能完成，但激活、图像 token、batch 和优化器必须实测 |
| 对 1B–3B VLM 做 LoRA/QLoRA | **CONDITIONAL-GO** | 适合作为首选大脑规模；上下文、图像数和视觉编码器冻结策略决定是否能跑 |
| 量化推理 7B–8B VLM | **CONDITIONAL-GO** | 可能放得下，但通常只能低频调用，不能据此宣称完整闭环实时 |
| 单卡完整微调 7B–8B VLM | **NO-GO** | 24 GB 显存不适合普通 AdamW 全参数微调 |
| 复现 REAL 一类在线 Agent RL | **NO-GO** | REAL 的 SFT 使用 8×A800，在线 RL 使用 8×RTX 4090，不是单卡方案 |
| Lite3 真机异步混合部署 | **CONDITIONAL-GO** | 是推荐结构，但目标机载计算设备、网络和 p99 闭环延迟尚未核验 |
| Lite3 真机全机载 1B–3B Agent | **证据不足** | 目标 Jetson 型号、内存和功耗没有冻结，当前不能承诺 |

因此，“单卡 4090 + 真机 Agent 可行”的准确说法是：

> 单卡 4090 足以开展轻量导航策略训练、小型 VLM 参数高效微调、量化推理和异步 Agent 原型研究；真机端优先采用小脑机载、大脑低频或远程运行的异步混合结构。完整可行性必须由实际机载设备、网络和全链路 p95/p99 测试确认。

## 2. 本文所说的“具身导航大脑 Agent”具体是什么

这里的 Agent 不是简单地把一句语言指令输入模型，再让模型输出一个动作。一个能称为具身导航 Agent 的系统，至少要形成下面的闭环：

1. **观察环境**：读取相机图像、机器人状态、当前任务和历史。
2. **形成中间目标**：决定下一步应去哪个门、走廊、物体或图像区域，而不是直接输出电机电流。
3. **调用能力**：把子目标交给局部导航、避障、转向、停止、询问等工具。
4. **检查进展**：判断是否接近目标、是否卡住、是否偏离、当前语义是否已经过期。
5. **恢复与交互**：需要时重新规划、回退、请求人类澄清或安全停车。
6. **保留任务状态**：知道已经尝试过什么、失败在哪里、当前还剩什么子任务。

对本项目而言，合理的 Agent 不是另起炉灶，而是在现有导航链上增加一层：

```text
任务 / 语言目标 / 目标图像
            |
            v
低频导航 Agent：理解任务、选择工具、生成子目标、检查进展、决定是否重规划
            |
            | 带时间戳、有效期、置信度、来源帧和来源位姿的子目标
            v
快速 NoMaD / TinyNavBrain：把当前图像与子目标变成 waypoint/action chunk
            |
            v
现有 waypoint-to-velocity adapter -> 安全桥 -> Lite3 底层运动控制
```

这样做的原因不是追逐“大模型”概念，而是让两个不同时间尺度的问题由不同模块处理：

- 语义理解、长期任务、失败恢复可以慢一些，但需要更强的推理能力。
- 避障、局部转向和安全停车必须快，而且不应依赖不稳定的网络或长时间生成。

## 3. 当前项目已经具备什么，还缺什么

### 3.1 已验证事实

| 已验证内容 | 具体结果 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| Lite3 导航接口 | waypoint policy → waypoint-to-velocity adapter → safety bridge/locomotion | Agent 可以复用已有局部导航工具接口 | 不证明新 Agent 已接入 |
| 名义导航频率 | `deployment/config/robot.yaml` 为 4 Hz | 可先用 250 ms 作为 System 1 名义周期 | 不证明全链路 p99 已达 4 Hz |
| TinyNavBrain 参数量 | 8,513,117 | 低层策略属于轻量模型 | 不证明训练后有效 |
| H0 图像前向 | 3.599 ms/batch | 4090 上单组件推理有很大时间余量 | 不是完整机器人循环 |
| H1 velocity 前向 | 4.627 ms/batch | 生成式预测头单组件可运行 | 不是闭环成功率 |
| H1 NFE=2 sample | 4.170 ms/batch | 少步生成接口可运行 | 不证明 NFE=2 足够好 |
| 图像前向峰值显存 | 156.56 MiB | 低层模型本身不构成 24 GB 显存瓶颈 | 不包含大脑、训练状态和完整输入缓存 |
| B0 管线测试 | H0/H1 各 200 optimizer steps；精确恢复通过 | loss/backward/checkpoint 管线接通 | 无正式评测，不能称为新模型训练结果 |
| 历史真机 sampled loop | 528 个采样；均值 2.89–7.02 Hz | 历史系统在部分配置下出现过接近或超过 4 Hz 的循环 | 不是连续 trace，不是 p99，也不能证明导航成功 |
| 历史真机试验 | 14 个冻结 trial、20 段视频 | 有可复核的真机素材 | `formal_outcome` 尚未人工确认 |

### 3.2 基于这些事实可以作出的推断

- 8.5M 参数低层策略不是单卡 4090 的主要算力风险。
- 现有 waypoint 接口适合被包装成 Agent 工具，不需要为了 Agent 重写 Lite3 全部控制链。
- 项目最缺的不是一个更大的低层网络，而是：
  - 长期任务和语义子目标；
  - 何时重新调用大脑；
  - 大脑输出过期时如何安全处理；
  - Agent 是否真的比纯局部策略改善复杂任务。
- 真正的实时瓶颈可能在图像预处理、VLM、通信、adapter、机器人接口或尾延迟，而不是 TinyNavBrain 单次前向。

### 3.3 仍未验证的假设

- 目标机载计算平台究竟是哪一款 Jetson、多少内存、多少功耗。
- 1B–3B VLM 在本项目实际图像数量、分辨率和提示长度下的 p50/p95/p99。
- 大脑与小脑同时驻留 4090 时的峰值显存和资源争用。
- 远程 4090 到 Lite3 的实际往返延迟、抖动、丢包和断网分布。
- 训练后的 TinyNavBrain 是否比公平 NoMaD/确定性基线更好。
- Agent 对本项目任务是否带来足够大的成功率、恢复率或人类交互收益。
- “按事件调用大脑 + TTL 安全契约”的完整组合是否已经被其他 2025–2026 工作覆盖。

## 4. NoMaD 到 2026 年是否已经过时

### 4.1 作为论文主要创新：已经过时

[NoMaD](https://arxiv.org/abs/2310.07896) 在 2023 年的重要贡献是把目标导航和无目标探索统一到 goal-masked diffusion policy 中，并展示多机器人数据训练和真机导航。

到 2026 年，如果论文的主要内容只是：

- 在 Lite3 上部署 NoMaD；
- 更换图像编码器；
- 调整 diffusion steps 或 CFG；
- 做单一数据集微调；
- 给 NoMaD 外面加一个普通 VLM；

那么很难形成足够强的新方法贡献。原因是后续工作已经把研究问题推进到：

- 语言和视觉目标的统一；
- 大模型生成中层子目标；
- 慢速推理与快速控制异步运行；
- 大模型延迟作为策略状态；
- 工具调用、记忆、询问和错误恢复；
- 小模型、量化、动作分块和端侧部署。

### 4.2 作为局部导航技能：没有过时

NoMaD 仍然可以承担下面的角色：

- 接收图像目标或局部子目标；
- 输出短期 waypoint/action chunk；
- 在大脑没有更新时保持短时局部运动；
- 在大脑失败时作为降级模式；
- 作为 Agent 工具和公平 baseline。

这与 A*、DWA、PID 在 REAL 中仍被使用的道理相同：上层 Agent 变强，不代表可靠的底层能力必须被删除。

因此，本项目不应继续把 NoMaD 当成最终“导航大脑”，也不应因为它发表于 2023 年就全部废弃。更准确的定位是：

> NoMaD/TinyNavBrain 从论文主角下沉为可训练、可替换、可测量的快速导航技能。

## 5. 2023–2026 具身导航 Agent 的研究演进

| 时期 | 主要问题 | 代表工作 | 对本项目的含义 |
|---|---|---|---|
| 2023 | 跨机器人视觉导航、目标导航和探索统一 | NoMaD、ViNT | 建立可迁移的 waypoint policy |
| 2024 | VLM 输出中层空间动作，运动策略负责执行 | NaVILA、RING、OK-Robot | 大模型不必直接控制高频底层 |
| 2025 | 双系统、异步推理、动作分块、小模型、流式导航 | DualVLN、StreamVLN、SmolVLA、VL-Nav、Hi Robot | 实时性通过分层和异步解决 |
| 2026 | 工具编排、交互询问、任务记忆、延迟显式建模 | TIC-VLA、REAL、Uni-LaViRA | Agent 的重点从“会预测动作”转向“会管理能力与失败” |

总体趋势不是所有系统都走向一个巨大的端到端模型。更常见的可部署结构是：

```text
大模型规模可以增长
        |
        v
只承担低频任务理解、子目标、工具调用、检查和恢复
        |
        v
轻量学习策略 / 传统规划 / 安全控制仍承担快速闭环
```

因此，“大家都在做大脑小脑和大模型 scale”这个观察基本成立，但不能推出“必须用大模型高频控制机器人”。从真机部署证据看，**分层、异步和模块化正是大模型进入机器人后保持实时性的主要方式**。

## 6. 五篇最关键论文的具体内容

### 6.1 NoMaD：统一目标导航和探索的扩散式局部策略

论文：[NoMaD: Goal Masked Diffusion Policies for Navigation and Exploration](https://arxiv.org/abs/2310.07896)

论文做了什么：

- 使用 goal masking 让同一个扩散策略支持有目标导航和无目标探索。
- 使用多机器人导航数据训练。
- 输出适合局部导航的动作/waypoint，而不是长期语言任务计划。

对本项目仍有价值的部分：

- 与现有 Lite3 waypoint 接口一致。
- 可以作为快速 System 1、Agent 工具和公平 baseline。
- 多数据集训练仍可能提高低层技能的视觉泛化。

不能继续声称的内容：

- NoMaD 本身是 2026 年的新 Agent 架构。
- diffusion waypoint 等于长期任务规划。
- 只要在新机器人上复现就足够构成方法论文。

### 6.2 NaVILA：8B 大模型给出中层空间动作，运动策略负责执行

论文：[NaVILA: Legged Robot Vision-Language-Action Model for Navigation](https://arxiv.org/abs/2412.04453)

论文 PDF：[USC Lira Lab](https://liralab.usc.edu/pdfs/publications/cheng2025navila.pdf)

体系结构：

- 高层 8B VLA 不直接输出每个电机动作。
- 它输出类似“向前移动 75 cm”的中层语言空间动作。
- 视觉运动强化学习策略负责把这个中层动作变成四足机器人运动。

RTX 4090 上的论文结果：

| 8B VLA 精度 | 单次推理时间 | 显存 | R2R SR | R2R SPL |
|---|---:|---:|---:|---:|
| FP16 | 594.58 ms | 18.5 GB | 49.7 | 45.5 |
| W4A16 | 367.80 ms | 8.6 GB | 48.2 | 43.6 |

这些数值说明：

- 8B 模型经过 4-bit 权重量化后可以放进 4090。
- 约 368 ms 的单次推理相当于理论上约 2.7 次/秒，尚未包括完整图像处理、通信和机器人控制开销。
- 它适合低频输出中层动作，不适合直接占用 4 Hz 或更快的全部安全控制周期。

不能由这些数值推出：

- 8B VLA 能在 Lite3 上完成 4 Hz 的完整闭环。
- 8B 模型可以在单卡 4090 上全参数训练。
- 量化后所有任务表现和真机安全均不受影响。

### 6.3 DualVLN / InternVLA-N1：2 Hz 大脑和 30 Hz 小脑异步协作

论文：[DualVLN: Dual-System Vision-Language Navigation](https://arxiv.org/abs/2512.08186)

官方训练说明：[InternNav Training Tutorial](https://internrobotics.github.io/user_guide/internnav/tutorials/training.html)

体系结构：

- `System 2` 使用 7B VLM，以约 2 Hz 生成全局规划信息。
- 它同时给出显式 pixel goal 和隐式 latent goal。
- `System 1` 是较小的 diffusion policy，以约 30 Hz 执行。
- 两者异步运行，大脑不阻塞快速动作循环。

论文还报告：

- System 1 使用约 1% 的轨迹数据已具有竞争力。
- 约 10% 的轨迹后接近饱和，主要瓶颈更偏向 System 2。
- 真机覆盖走廊、卧室和办公室等场景，每种场景每个模型进行 20 次试验。

对本项目的启示：

- TinyNavBrain 不需要承担全部语义推理。
- System 1 小而快是合理设计，而不是落后设计。
- 研究重点可以从继续扩大低层策略，转到提高大脑的子目标质量和调用效率。

### 6.4 TIC-VLA：把大模型延迟和机器人自运动显式输入快速策略

论文：[TIC-VLA: Time-Informed Correction for Vision-Language-Action Navigation](https://arxiv.org/abs/2602.02459)

论文 HTML：[arXiv full text](https://arxiv.org/html/2602.02459v2)

这是与本项目拟议方向最接近、也最需要避免重复的工作。

体系结构：

- 慢速 VLM 使用 InternVL3-1B。
- 快速 action policy 与 VLM 异步运行。
- 策略不仅接收较早生成的语义状态，还接收：
  - 延迟时间 `Δt`；
  - 从语义帧到当前帧之间的自运动偏移。
- 训练时注入 0–10 秒延迟。
- VLM 和视觉编码器在动作强化学习阶段冻结。

论文运行设置：

| 模块 | 频率/硬件 |
|---|---|
| VLM | 0.5 Hz |
| action policy | 10 Hz |
| 真机机载端 | Jetson Orin NX，25 W |
| 外部计算 | RTX 4060 laptop，50 W |
| 机器人 | Unitree Go2 |
| VLM SFT | 8×L40S |
| action RL | 单张 L40S，400 iterations |

对本项目的直接约束：

- “1B 小模型大脑”不是新的。
- “慢大脑 + 快小脑”不是新的。
- “异步运行”不是新的。
- “延迟作为输入”和“训练时注入 0–10 秒延迟”也不是新的。

本项目若继续 Agent 方向，必须把贡献推进到尚未被上述内容覆盖的组合，例如：

- 根据不确定性、任务进展和失败风险决定**何时调用大脑**，而不是固定 0.5 Hz；
- 把一次大脑调用的收益、时间、能耗和网络代价作为共同预算；
- 对每个子目标附加来源帧、来源位姿、置信度和 TTL；
- 把“最多还能执行多远/多久，然后必须停车”变成可测的安全契约；
- 在 Lite3 图像目标导航和单 4090 约束下进行完整消融。

在立项前还必须继续做一次针对“event-triggered VLM invocation、TTL fallback、bounded continuation”的排除性文献检索。若已有工作完整覆盖，就不能使用这组内容作为主要 novelty。

### 6.5 REAL：8B 高层 Agent 调用工具，而不是高频控制机器人

论文：[REAL: An Interactive and Lifelong Robot Agent](https://arxiv.org/abs/2607.13653)

可检索全文：[alphaXiv full text](https://www.alphaxiv.org/abs/2607.13653)

REAL 的重要性不在于它证明“大模型可以实时控制机器人”，恰恰在于它展示了另一种方式：

- 高层使用 Qwen3-VL-8B。
- 高层 Agent 观察 RGB/SoM 图像、任务文本和工具返回结果。
- Agent 通过统一 MCP 接口调用导航、开放词汇感知、VLA 操作和人机交互工具。
- 从仿真转到真实机器人时，高层接口保持不变，只替换工具后端。

训练算力：

| 阶段 | 论文使用算力 |
|---|---|
| SFT | 8×NVIDIA A800，BF16，context 8192 |
| 在线 GSPO/RL | 单个 8-GPU RTX 4090 节点：2 张用于 vLLM rollout，6 张用于训练 |

因此，REAL 不能作为“单张 4090 可以训练同类 Agent”的证据。

真实机器人系统：

- 平台：ARX LIFT2 双臂移动机器人。
- 导航：ConceptGraph + RealSense D455；Odin1 深度/SLAM；A*、DWA、PID。
- 操作：调用 Pi-0.5 等低层技能。
- 关键含义：即使高层使用 8B Agent，传统规划、定位、控制和低层 VLA 仍是系统主体。

真实机器人具体结果：

三类真实任务分别是：

- FDO（Furniture-Distractor Open/Close）：在有家具干扰项的环境里完成开门、关门或抽屉操作。
- FODP（Furniture & Object-Distractor Pick-and-Place）：在家具和物体都存在开放词汇干扰项时完成取放。
- SUL（Simulator-User-Loop）：指令故意保留歧义，Agent 需要判断是否先向用户提问再执行。

| 结果类别 | 具体结果 |
|---|---:|
| 导航/注视重复性试验 | 30 次 |
| 里程计位置误差 | 1.78 ± 0.40 cm |
| 偏航误差 | 0.74 ± 0.57° |
| 图像位移 RMSE | 21.5 ± 10.4 px |
| 低层 primitive 执行 | 600 次 |
| primitive 总体成功率 | 85.3% |
| Open | 63.3% |
| Close | 100% |
| Pick | 89.2% |
| Place-desk | 100% |
| Place-microwave | 74.2% |
| 真实端到端 episode | 60 次 |
| 总体成功率 | 78.3% |
| FDO | 80% |
| FODP | 100% |
| SUL | 55% |
| 平均步骤数 | 11.6 |
| SPL | 63.1% |
| 平均 Ask 次数 | 0.72 |
| 每个 episode 累计高层 VLM 延迟 | 68.4 s |

REAL 还报告：

- 每个 Pi-0.5 操作 primitive 包含 1000 个低层控制 step，按 50-step chunk 执行，实际动作约 60 秒。
- 60 个真实 episode 的失败中，高层视觉理解错误只占少数；更多失败来自低层 VLA、超时和未触发询问。

这些结果支持的结论：

- Agent 可以通过工具调用完成长时程任务。
- 高层模型可以很慢，只要它不阻塞高频运动控制。
- 系统最终表现仍受低层技能可靠性约束。
- “大脑更大”不能自动修复导航、操作和安全控制失败。

这些结果不支持的结论：

- Qwen3-VL-8B 可以在单卡 4090 上完成 REAL 的训练。
- 68.4 秒累计延迟满足高频控制。
- 把 Lite3 的 NoMaD 换成大模型就能得到相同成功率。

## 8. 单卡 4090 可行性：必须拆成五个问题

### 8.1 小模型训练是否可行

对 TinyNavBrain 量级，当前答案是 **工程管线可行**：

- 8.5M 参数；
- H0/H1 各完成 200 optimizer steps；
- step 中位约 79 ms；
- step p95 约 96–100 ms；
- 训练 step 峰值显存约 479–489 MiB；
- exact-resume 通过。

但这仍是 Go Stanford 5% 子集上的 plumbing smoke，没有验证集评测和模型效果。准确表述应为：

> 单卡 4090 已经跑通 TinyNavBrain 的小规模训练基础设施，不是已经完成正式训练。

### 8.2 较大模型全参数训练是否可行

用普通 AdamW 混合精度训练作粗略下界估算：

```text
BF16 参数             2 bytes/parameter
BF16 梯度             2 bytes/parameter
FP32 master weights   4 bytes/parameter
FP32 Adam 一阶/二阶矩 8 bytes/parameter
合计约                16 bytes/parameter
```

这还没有包含激活、临时 buffer、视觉 token 和框架开销。

| 参数量 | 仅模型训练状态粗估 | 单卡 24 GB 判断 |
|---:|---:|---|
| 20M | 0.32 GB | 明确可行 |
| 450M | 7.2 GB | 可能可行，激活和 batch 是关键 |
| 1B | 16 GB | 很紧，普通全参训练通常不值得作为首选 |
| 3B | 48 GB | 普通全参训练不可行 |
| 7B | 112 GB | 不可行 |
| 8B | 128 GB | 不可行 |

这是估算，不是项目实测。8-bit optimizer、ZeRO/offload、梯度检查点会改变上限，但也增加速度和工程成本。

### 8.3 LoRA/QLoRA 是否可行

对 1B–3B 级大脑，推荐优先：

- 冻结视觉编码器或大部分 VLM；
- 使用 LoRA/QLoRA；
- 输出短结构化 token，而不是长篇自然语言；
- 限制图像数量、分辨率和上下文；
- batch 从 1 开始实测；
- 先做 SFT，不做大规模在线 RL。

当前判断为 **CONDITIONAL-GO**，原因是权重显存通常不是唯一问题，图像 token、激活和 attention 上下文可能成为主要开销。

### 8.4 量化推理是否可行

仅按权重计算的理论下界：

| 参数量 | BF16 权重 | INT4 权重理论下界 |
|---:|---:|---:|
| 450M | 0.9 GB | 0.225 GB |
| 1B | 2 GB | 0.5 GB |
| 3B | 6 GB | 1.5 GB |
| 8B | 16 GB | 4 GB |

实际显存会更高，因为还包含 KV cache、视觉编码器、量化元数据、中间激活和运行时 buffer。

NaVILA 的 8B W4A16 实测为 8.6 GB、367.80 ms，证明“8B 量化后能放进 4090”，但不证明“8B 完整 Agent 能在 Lite3 上实时闭环”。

### 8.5 完整真机闭环是否可行

完整闭环至少包含：

```text
相机取帧
-> 图像预处理
-> System 2（仅触发时）
-> 子目标消息传输
-> System 1
-> waypoint adapter
-> 安全桥
-> ROS/机器人通信
-> 执行反馈
```

现在只测过其中一部分。必须新增：

- 各模块 p50/p95/p99；
- 4 Hz deadline miss rate；
- 大脑调用期间 System 1 是否抖动；
- GPU 共驻留时显存峰值；
- 30–60 分钟热稳态；
- 远程网络 RTT、抖动、丢包和断网；
- TTL 到期到实际停止的距离和时间。

## 9. 三种真机体系结构

### 9.1 全机载大脑和小脑

```text
Lite3 机载设备：VLM Agent + TinyNavBrain + adapter + safety
```

优点：

- 不依赖外部网络；
- 延迟来源较少；
- 机器人数据不离机。

当前问题：

- 目标机载设备型号、RAM、功耗和软件栈尚未冻结；
- 1B–3B VLM 的实际端侧速度未知；
- 不能因为 VL-Nav 在 Orin NX 上达到 30 Hz，就推断本项目的通用 Agent 也能达到。

当前结论：**证据不足，不作为第一实现路径。**

### 9.2 远程 4090 大脑，机载小脑

```text
远程 4090：VLM Agent
        |
        | 网络子目标
        v
Lite3 机载：TinyNavBrain + adapter + safety
```

优点：

- 可以使用更大模型；
- 训练和推理环境统一；
- 机载端负担小。

风险：

- 网络断开、抖动和延迟；
- 当前 4090 GPU live gate 本身失败；
- 如果机器人边运动边等待网络，风险不可接受。

当前结论：**修复 4090 后可做实验原型，但必须有本地 TTL 和停车保护。**

### 9.3 异步混合：推荐方案

```text
                         +-----------------------------+
任务/图像/状态 ----------> 低频或事件触发的 VLM Agent |
                         +--------------+--------------+
                                        |
                     subgoal + confidence + timestamp
                     + TTL + source frame/pose + tool
                                        |
                                        v
相机 ------> TinyNavBrain / NoMaD System 1 ------> waypoint
                    ^                               |
                    |                               v
            进展/不确定性监测                adapter + safety
                    |                               |
                    +-----------反馈----------------+
                                                    |
                                                    v
                                                  Lite3
```

推荐初始频率只作为待验证设计值：

- System 1：先遵守当前 4 Hz 合同。
- System 2：0.2–1 Hz 或按事件触发。
- 安全桥和底层运动控制：保持现有实现，不由 VLM 接管；实际频率另行测量。

推荐原因：

- 与现有项目接口最一致；
- 能使用单 4090 上的 1B–3B 大脑，也允许以后迁移到端侧；
- 大脑变慢不会直接阻塞每个控制周期；
- 可以把网络和陈旧语义变成明确的研究变量。

## 10. 大脑到小脑的消息合同

建议每个 Agent 子目标至少包含：

```yaml
task_id: string
subgoal_id: string
tool_name: navigate_pixel_goal | navigate_image_goal | stop | ask | backtrack
source_frame_id: string
source_timestamp_ms: int
source_pose: [x, y, yaw]
pixel_goal: [u, v] | null
goal_image_id: string | null
confidence: float
ttl_ms: int
max_execution_ms: int
max_execution_distance_m: float
reason_code: string
```

小脑执行前必须检查：

- 当前时间是否超过 TTL；
- 机器人是否已经相对来源位姿移动过远；
- 来源帧是否与当前相机/任务一致；
- 置信度是否低于阈值；
- 当前是否有碰撞风险、无进展或人工停止。

安全状态机：

```text
VALID_SUBGOAL
    -> 执行一个有界 waypoint chunk
    -> 检查进展与剩余 TTL
    -> 继续 / 请求更新

STALE_OR_NETWORK_LOSS
    -> 不接收新长程动作
    -> 只允许当前有界 chunk 完成或立即取消
    -> 安全停车 / 低速回退

LOW_CONFIDENCE_OR_NO_PROGRESS
    -> 触发大脑重规划、询问或 backtrack
```

## 11. 最值得研究的三个 idea

评分为当前证据下的研究判断，不是论文接受概率。

| Idea | 重要性 | 新颖性 | 单卡可行性 | 真机可证伪性 | 主要风险 |
|---|---:|---:|---:|---:|---|
| 预算自适应、按事件调用大脑的导航 Agent | 5 | 4 | 4 | 5 | 可能已有相近 event-trigger 工作 |
| 带来源位姿和 TTL 的有界陈旧语义安全契约 | 5 | 3 | 5 | 5 | 容易被认为是工程安全层 |
| 带记忆、询问和回退的工具化轻量导航 Agent | 4 | 3 | 4 | 4 | 系统集成多，方法贡献可能不集中 |

### 11.1 首选：预算自适应、按事件调用大脑的导航 Agent

暂定题目：

> **Budget-Adaptive Event-Triggered Navigation Agent with Bounded-Staleness Control**

核心问题：

> 在单卡 4090 和真机实时预算下，什么时候调用视觉语言大脑，才能比固定频率调用获得更好的任务成功率、延迟、能耗和安全折中？

与 TIC-VLA 的预期差异：

- TIC-VLA 重点是大脑结果已经延迟时，快速策略如何利用延迟和自运动信息进行修正。
- 本 idea 重点是大脑调用本身是一种昂贵资源，系统根据不确定性、无进展、场景变化和任务阶段决定是否调用。
- 每次调用生成带来源和 TTL 的有界子目标；过期后不能无限执行。

需要验证的假设：

- H1：事件触发比固定 0.5 Hz/1 Hz 调用减少 VLM 次数，同时不降低成功率。
- H2：在相同延迟和丢包条件下，来源/TTL 契约比无契约异步系统降低错误子目标执行距离。
- H3：相对纯 TinyNavBrain，Agent 只在长时程、语义歧义、路线恢复等任务上带来显著收益。
- H4：若简单任务中 Agent 无收益，系统能够少调用或不调用大脑，而不是强制增加延迟。

### 11.2 备选一：双系统导航的延迟、断网和陈旧子目标基准

如果方法 novelty 不足，可以收缩成严格的 failure-injection benchmark：

- 固定计算、模型和任务；
- 注入 0–10 秒延迟、抖动、丢包、断网和错误置信度；
- 比较同步、固定频率异步、延迟感知异步、事件触发异步；
- 提供错误子目标执行距离、停车时间、deadline miss 和恢复率。

风险：单独 benchmark 的投稿价值取决于任务覆盖和社区复用性，不能只有本项目一套走廊试验。

### 11.3 备选二：轻量工具化导航 Agent

把现有能力明确包装为工具：

- `navigate_image_goal`
- `navigate_pixel_goal`
- `rotate_and_observe`
- `stop`
- `ask_human`
- `backtrack`

Agent 维护任务清单、已访问位置、失败工具和恢复历史。

风险：如果只是编排现有工具，容易被评价为系统工程。必须通过长时程任务、交互询问和失败恢复的可量化增益来支撑。

## 12. 首选 idea 的可证伪实验

### 12.1 必须比较的系统

| 编号 | 系统 | 目的 |
|---|---|---|
| A | NoMaD/TinyNavBrain only | 判断 Agent 是否真的必要 |
| B | 同步 VLM + System 1 | 展示阻塞式方案的延迟与安全代价 |
| C | 固定频率异步 VLM + System 1 | 对照 DualVLN/TIC-VLA 类结构 |
| D | 固定频率异步 + 延迟/自运动信息 | 避免把 TIC-VLA 已有思想当成新收益 |
| E | 事件触发 + 来源/TTL + 有界回退 | 本项目候选方法 |

### 12.2 任务层级

- 简单局部图像目标：理论上 System 1 已足够。
- 多岔路长走廊：需要语义子目标和重规划。
- 目标描述有歧义：需要询问或重新观察。
- 临时遮挡/路线受阻：需要恢复或 backtrack。
- 网络延迟和断网：检验异步安全契约。
- 大脑给出错误子目标：检验置信度、TTL 和停止。

### 12.3 指标

任务效果：

- Success Rate
- SPL
- collision rate
- intervention rate
- recovery success
- Ask 次数和有效 Ask 比例

实时性：

- System 1 与 System 2 的 p50/p95/p99
- 完整循环 p50/p95/p99
- 4 Hz deadline miss rate
- 每个 episode 的 VLM 调用次数
- 每个 episode 的累计 VLM 等待时间

陈旧语义与安全：

- subgoal age
- stale-subgoal execution distance
- TTL 到期到实际停车的时间和距离
- 网络断开后的最大继续运动距离
- 错误子目标被接受的比例

资源：

- 峰值显存
- GPU 利用率
- 功耗和热稳态
- token/image 数
- 单任务推理成本

### 12.4 直接停止 Agent 主线的证伪条件

满足以下任意一项，就不应继续把 Agent 作为主要论文方向：

1. 训练后的 System 1 在基础任务上本身不能达到可用成功率。
2. Agent 在长时程或恢复任务上相对 System 1 没有统计显著收益。
3. 事件触发方案相对固定频率延迟感知 baseline 没有收益。
4. 1B–3B 大脑量化后仍无法满足显存或调用延迟预算。
5. 实际网络延迟使系统大部分时间处于停车/回退，Agent 基本不能贡献。
6. 真实机载设备无法运行 System 1 或无法保障安全停车。
7. 排除性文献检索发现已有工作完整实现并验证事件触发、TTL、来源位姿和有界停车组合。
8. 贡献只能描述为“集成了 VLM”，无法形成独立、可测、可复现的方法差异。

## 13. 从现在到训练前的可执行 backlog

本阶段遵守“先完成无需实际训练的本地基础设施和测试，再由用户决定外部数据获取与训练执行”。

### 13.1 Windows：研究主控、合同和无训练测试

1. 冻结 Agent→System 1 的消息 schema 和状态机。
2. 实现不依赖真实数据的 fake Agent、fake delay、fake packet loss。
3. 为 TTL、来源帧、来源位姿、低置信度、断网和取消编写单元测试。
4. 建立统一 timing trace schema，记录每个模块的开始、结束、deadline 和失败原因。
5. 建立模型资源估算表，明确候选 0.5B、1B、3B、7B 的精度、上下文和显存测试配置。
6. 完成针对 event-triggered VLM invocation 和 TTL fallback 的排除性文献检索。

完成标准：

- 不下载完整数据集；
- 不运行正式训练；
- 测试使用合成消息和历史小样本；
- 不能把 scaffold 或测试通过写成 Agent 效果。

### 13.2 Ubuntu：仿真中的异步与故障注入

1. 在现有仿真链加入异步大脑 stub。
2. 注入固定延迟、随机抖动、丢包、断网和陈旧子目标。
3. 验证 TTL 到期、取消、停车和 backtrack 状态机。
4. 先使用 oracle/fake subgoal，避免把模型错误和系统错误混在一起。
5. 只有基础设施通过后，才接真实 VLM 输出。

不能重复 U00–U18，也不能覆盖 U09 v0.3 或 U10 v5。新 Agent 试验必须使用新目录、新协议和新的 `SIM-GATE`。

### 13.3 4090：数据、训练和模型推理

在用户决定训练前，只做：

1. 修复并核验 `/dev/nvidia*` 和 `nvidia-smi`。
2. 冻结 GPU、驱动、CUDA、容器和磁盘收据。
3. 对候选 VLM 做 inference-only microbenchmark：
   - 精度；
   - 分辨率；
   - 图像数；
   - prompt 长度；
   - 输出 token；
   - p50/p95/p99；
   - 峰值显存。
4. 测试 VLM 与 TinyNavBrain 共驻留，不运行训练。

用户授权训练后，再按顺序：

1. 恢复并核验公平 NoMaD/确定性/TinyNavBrain baseline。
2. 完成多数据集正式训练和评测。
3. 选择最小可用 System 2。
4. 优先 SFT/LoRA/QLoRA。
5. 只有离线和仿真证明 Agent 有增益后，才考虑更昂贵的 RL。

完整数据集继续只存放在 4090 服务器；Windows 和 Ubuntu 不复制全量数据。

## 14. 真机前必须由人确定的硬件事实

| 必须确认 | 为什么影响结论 |
|---|---|
| Lite3 机载计算设备准确型号 | 决定模型能否机载 |
| GPU/CPU/NPU、统一内存和可用内存 | 决定精度和上下文 |
| 功耗模式与散热 | 决定持续运行而非短 benchmark |
| 相机型号、分辨率、帧率和时间戳 | 决定图像延迟与帧来源 |
| 机载 ROS/系统版本 | 决定部署工具链 |
| 4090 与机器人网络方式 | 决定 RTT、抖动和断网行为 |
| 是否允许数据/图像离开机器人 | 决定能否远程大脑 |
| 现有 e-stop、heartbeat 和安全责任边界 | 决定 Agent 能控制到哪一层 |

在这些事实未冻结前，“全机载 Agent”保持未验证；可以做协议和仿真，但不能承诺真机性能。

## 15. 最终决策门

### 允许继续 Agent 方向

需要依次满足：

1. **文献门**：明确区别于 TIC-VLA、DualVLN 和 REAL，且 event-trigger/TTL 组合未被完整覆盖。
2. **4090 门**：GPU live gate 修复；候选 VLM 和 System 1 共驻留时显存、p95/p99 可接受。
3. **低层能力门**：训练后的 NoMaD/TinyNavBrain 至少在基础任务上可靠。
4. **仿真门**：故障注入下不会无限执行陈旧子目标，停车边界可复现。
5. **Agent 价值门**：在长时程、语义歧义或恢复任务上超过纯 System 1。
6. **真机门**：目标设备冻结；完整链路 p99、deadline miss、热功耗和安全停车通过。

### 不允许继续 Agent 方向

- 只是把 VLM 加在现有策略前面；
- 只有推理 demo，没有公平 baseline；
- 只有均值 latency，没有尾延迟和失效行为；
- 用 REAL 的 8×4090 结果证明单卡训练；
- 用随机初始化前向证明模型效果；
- 用 scaffold、计划或消息 schema 证明 Agent 已经成功；
- 不能证明 Agent 相对纯导航策略带来任务层收益。

## 16. 回答用户提出的两个基本结论

### 基本结论 1：工作能否朝 Agent 方向发展

**能，但属于有条件转向。**

应当保留现有 NoMaD/TinyNavBrain 和 Lite3 安全控制链，把它们变成 Agent 可调用的快速导航技能。新研究问题不再是“把 NoMaD 做得更像一个大脑”，而是：

> 在单卡和真机实时预算下，如何让低频视觉语言 Agent 只在必要时介入，并让过期、错误或丢失的大脑输出受到明确安全边界约束。

如果后续证明 Agent 对长时程、语义歧义和恢复任务没有收益，或者 novelty 被已有工作覆盖，就不应继续 Agent 主线。

### 基本结论 2：单卡 4090、真机部署、体系结构和可研究 idea

- 单卡 4090 足以训练 TinyNavBrain 量级模型。
- 单卡 4090 适合对 1B–3B 大脑做 LoRA/QLoRA 和量化推理研究。
- 单卡 4090 不适合普通方式全参数微调 7B–8B，也不能复现 REAL 的 8-GPU 在线 Agent RL。
- 真机推荐异步混合体系：机载快速 System 1 与安全控制，低频/事件触发 System 2 可先运行在远程 4090，后续再根据真实 Jetson 规格决定是否机载。
- 最值得研究的 idea 是“预算自适应、按事件调用大脑，并带来源/TTL/有界停车的导航 Agent”。
- 这个 idea 必须以固定频率延迟感知系统为强 baseline，并通过延迟、断网、错误子目标和实际真机 p99 直接证伪。
