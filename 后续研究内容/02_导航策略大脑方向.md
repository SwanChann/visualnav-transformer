# TinyNavBrain：小型生成式导航策略设计

更新日期：2026-07-10

## 1. “导航大脑”的严格定义

本研究中的 navigation brain 是一个小型、可训练、可评估的生成式策略核心：

> 它根据当前与历史视觉、目标图像、近期动作和物理尺度，生成多模态局部 waypoint/action chunk，并输出目标进展与置信度。

它不承担：

- 开放词汇语言推理。
- 高清未来视频生成。
- 全局地图构建。
- 低层腿足 locomotion。
- 通用机器人 foundation model。

Lite3 低层控制、velocity adapter、heartbeat、timeout 和 emergency stop 继续复用现有系统。

## 2. 问题定义

输入：

~~~
O_t = {o_(t-C), ..., o_t}       observation history
g                              goal image
A_t = {a_(t-H), ..., a_(t-1)}  action history
m = {dataset, dt, metric scale, camera metadata}
b                              inference budget / NFE
~~~

输出：

~~~
K waypoint/action chunks
goal progress or temporal distance
predictive confidence / uncertainty
~~~

目标是在固定参数量和计算预算下学习：

~~~
p(a_(t:t+T) | O_t, g, A_t, m, b)
~~~

主要评价不是单一 imitation error，而是 held-out dataset 和 closed-loop 中的导航行为。

## 3. 推荐模型

### 3.1 总体结构

~~~
Observation / Goal Images
        |
Compact Visual Encoder
        |
Temporal + Goal Token Fusion
        |---------------- Action History / Scale Token
        |
Conditional Generative Head
        |---------------- Progress Head
        |---------------- Confidence Head
        |
Waypoint Chunks -> Lite3 Adapter / Simulator
~~~

### 3.2 Compact visual encoder

第一阶段对比两类 encoder：

1. EfficientNet-B0：与 NoMaD 基线兼容，端侧成本低。
2. compact ViT/MobileViT：验证 transformer 表示是否值得额外延迟。

DINOv2/DINOv3 可以作为冻结 feature baseline，但不应默认成为最终端侧 backbone；否则“小模型”只指 trainable head，整体系统并不小。

必须同时报告：

- trainable parameters。
- total parameters。
- FLOPs 或可替代的计算量估计。
- workstation latency。
- Jetson/目标设备 end-to-end latency。

### 3.3 Temporal and goal fusion

建议：

- 3–5 帧 observation history。
- goal image 单独编码。
- 2–4 层、hidden size 192–256 的小型 Transformer。
- action history 和 physical scale 作为显式 token。

action history/scale conditioning 是必要 baseline，不是独立 novelty；VISTA 已直接研究这一问题。

### 3.4 Generative head

推荐优先比较：

1. NoMaD Conditional U-Net / DDIM。
2. conditional flow matching 或 rectified-flow head。
3. deterministic waypoint regression。

主模型可采用 conditional flow matching：

- waypoint 维度低，适合小网络。
- 可以统一测试 NFE=1/2/4/8。
- 比从头实现大型 diffusion transformer 更适合单卡 4090。

但不能预设 flow 一定优于 diffusion。它必须在相同 encoder、参数量、训练 step 和 NFE 下对比。

### 3.5 Auxiliary heads

只保留两个与任务直接相关的 head：

- temporal distance / goal progress。
- predictive confidence。

confidence 不能只用训练 loss 自我定义。应评估：

- waypoint error calibration。
- candidate coverage。
- OOD/corruption 下的 selective risk。
- closed-loop failure 前是否能发出高不确定性。

首篇不加入 VLM、memory graph、pixel world model 或 RL critic。

## 4. 数据统一表示

建议新增统一样本 schema：

~~~
dataset_id
trajectory_id
timestamp / dt
robot_or_platform
camera metadata if available
metric_waypoint_spacing
observation_paths[C]
goal_path
action_history[H, 2]
future_waypoints[T, 2]
temporal_distance
split
~~~

动作统一要求：

1. 全部转换到当前 body frame。
2. 保留 metric units。
3. 同时保存 normalized action 与真实尺度。
4. 保存 dt 和 waypoint spacing，禁止只保留 dataset-specific normalized value。
5. 不同数据集的 train/val/test split 按 trajectory/environment 划分，避免相邻帧泄漏。

## 5. 多数据集训练范式

### 5.1 必须比较的 mixture

| Mixture | 用途 |
|---|---|
| single dataset | specialist baseline |
| proportional sampling | 复现大数据集主导的常见训练 |
| dataset-balanced sampling | 控制每个数据集贡献 |
| temperature sampling | 平衡规模与覆盖 |
| leave-one-dataset-out | 测试真实 cross-dataset transfer |

### 5.2 训练顺序

第一阶段：

~~~
Go Stanford -> pipeline correctness
~~~

第二阶段：

~~~
Go Stanford + RECON + SACSoN/SCAND
~~~

第三阶段：

~~~
加入 TartanDrive 作为大动作尺度/户外 domain stress test
~~~

实际数据组合取决于下载许可、处理成功率和磁盘预算。文档中的数据集名称不是“已经可用”的承诺。

### 5.3 Loss

建议最小目标：

~~~
L = L_generative
  + lambda_d * L_temporal_distance
  + lambda_c * L_confidence_calibration
~~~

不建议首版加入：

- collision reward（公共数据通常没有可靠标签）。
- heuristic TTS score imitation。
- domain adversarial loss。
- RL objective。

这些会让错误来源难以定位。

## 6. Diagnostic benchmark

### Track A：IID

每个数据集独立 train/test，回答模型是否正常学习。

### Track B：Mixed-domain

多数据集训练、各域测试，比较 proportional/balanced/temperature mixture。

### Track C：Leave-one-dataset-out

训练 N-1 个数据集，测试完全 held-out dataset，作为核心泛化结果。

### Track D：Controlled corruption

- brightness/contrast。
- motion blur。
- sunflare。
- crop/FOV change。
- frame drop/stale observation。
- action-scale perturbation。

### Track E：Closed-loop

在重新设计的 MuJoCo/其他 simulator 中测试：

- randomized start/goal。
- 随机障碍物与非中心线任务。
- camera shake 和 latency injection。
- 至少 20 seeds/config。
- 禁止隐藏参考路径或 oracle correction。

## 7. 指标

### Offline

- minADE@K / minFDE@K。
- best-of-K coverage。
- diversity 与 mode coverage。
- temporal-distance error。
- calibration error / risk-coverage。
- parameters、NFE、mean latency、per-call p95。

ADE/FDE 不能单独决定优劣，因为导航动作可能多模态。

### Closed-loop

- success rate。
- SPL/path efficiency。
- collision count/rate。
- final distance。
- recovery/stuck/fall。
- end-to-end control frequency。
- compute-normalized success。

## 8. Baselines

最低 baseline 集：

1. frozen published NoMaD。
2. Go-Stanford-only NoMaD retraining。
3. multi-dataset NoMaD retraining。
4. same-encoder deterministic waypoint model。
5. same-budget DDIM-2/3。
6. action-history/scale-conditioned baseline。
7. TinyNavBrain NFE=1/2/4。

如果无法公平训练 multi-dataset NoMaD，就不能把 TinyNavBrain 的提升归因于新模型。

## 9. 必做消融

- single vs multi-dataset。
- proportional vs balanced sampling。
- without/with action history。
- without/with scale token。
- deterministic vs diffusion vs flow。
- NFE=1/2/4/8。
- model size small/medium。
- auxiliary confidence head。

## 10. 成立条件

TinyNavBrain 只有同时满足以下条件才构成“导航大脑”研究：

1. 在至少两个 held-out 或 strong-shift test 上稳定优于强 baseline。
2. 结果不是由更多参数、更多训练 step 或更高 NFE 造成。
3. 闭环 collision/SPL 至少一项稳定改善。
4. confidence 能预测失败或支持安全 fallback。
5. 端侧频率满足真实控制要求。

否则它只是一个新的 action decoder。
