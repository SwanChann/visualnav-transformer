# 多数据集与单卡 4090 实施路线

更新日期：2026-07-10

## 1. 当前资源审计

### 已具备

- RTX 4090 单卡训练资源。
- NoMaD/ViNT 训练代码和 ViNT_Dataset。
- processed Go Stanford：3696 trajectories、201822 images。
- Lite3 adapter、安全桥、MuJoCo 和冻结真机素材。
- 已有 NoMaD weights 和离线 inference pipeline。

### 尚未具备

- 可直接训练的 RECON。
- 可直接训练的 SACSoN/HuRoN。
- 可直接训练的 SCAND。
- 可直接训练的 TartanDrive。
- 统一多数据集 manifest。
- leave-one-dataset-out split。
- 有区分度的 closed-loop benchmark。
- 一个可稳定导入训练、分析和仿真的单一环境。

本地 recon_datavis 是可视化工具；本地 tartan_drive 是项目源码。二者都没有 traj_data.pkl，不能计入“已有训练数据”。

## 2. 第一阶段：数据可行性审计

在下载大数据前建立 data acquisition matrix：

| 数据集 | 是否公开 | 许可 | 原始格式 | 预计存储 | 处理脚本 | metric scale | 是否采用 |
|---|---|---|---|---:|---|---:|---|
| Go Stanford | 已有 | 待记录 | processed images + odom | 约 0.8 GB | 已完成 | 0.12 m | 是 |
| RECON | 公开/需核验入口 | 待核验 | HDF5 | 待测 | process_recon.py | 0.25 m | 优先 |
| SACSoN/HuRoN | 需按官方入口核验 | 待核验 | rosbag/发布格式 | 待测 | process_bags/custom | 0.255 m | 候选 |
| SCAND | 需按官方入口核验 | 待核验 | rosbag | 待测 | process_bags | 0.38 m | 候选 |
| TartanDrive | 公开但处理较重 | 待核验 | multimodal off-road | 大 | custom | 0.72 m | stress test |

验收：

- 每个采用的数据集至少抽查 20 trajectories。
- 图像编号、position、yaw、时间顺序一致。
- 记录许可和下载来源。
- 不把无法重分发的数据打包进公开 benchmark。

## 3. 第二阶段：统一数据层

建议代码资产：

~~~
scripts/research/data/build_nav_manifest.py
scripts/research/data/audit_nav_dataset.py
scripts/research/data/build_cross_dataset_splits.py
scripts/research/data/compute_dataset_stats.py
~~~

建议输出：

~~~
results/research/data_audit/dataset_manifest.csv
results/research/data_audit/dataset_stats.json
results/research/data_audit/split_audit.md
~~~

必须检查：

- trajectory-level leakage。
- 同一环境的近重复路线泄漏。
- observation/goal 时间间隔分布。
- metric waypoint spacing。
- frame rate/dt。
- 图像分辨率/FOV。
- 动作幅值和转向分布。
- 每个数据集的有效训练样本数。

## 4. 第三阶段：benchmark-first baseline

先跑 baseline，再设计新模型。

### B0：pipeline sanity

- Go-Stanford-only NoMaD。
- published checkpoint offline evaluation。
- 确认训练 loss、trajectory visualization 和指标复现。

### B1：single-dataset specialists

- 每个可用数据集独立训练同一模型。
- 固定参数量、epoch/step、augment 和随机种子。

### B2：multi-dataset NoMaD

- proportional sampling。
- balanced sampling。
- temperature sampling。

### B3：compact deterministic policy

- 与 TinyNavBrain 使用相同 encoder/fusion。
- 只替换为 deterministic regression head。

### B4：action-history/scale baseline

- 检验 VISTA 指出的部署尺度问题。
- 不是本文方法，而是必须对照。

只有 B0–B4 完整后，才能判断新 generative head 是否有价值。

## 5. 第四阶段：TinyNavBrain

### 推荐规模

以 pilot 为准，不承诺未经测量的训练时长：

| 组件 | 目标 |
|---|---|
| image size | 96×96 或 128×128 |
| context | 3–5 frames |
| hidden dim | 192–256 |
| fusion layers | 2–4 |
| waypoint horizon | 8 |
| trainable params | 目标 <20M |
| total params | 必须单独报告 |
| NFE | 1/2/4/8 |
| seeds | 至少 3 |

### 推荐代码资产

~~~
scripts/research/models/tinynav_brain.py
scripts/research/train_tinynav_brain.py
scripts/research/eval_cross_dataset.py
scripts/research/eval_corruptions.py
scripts/research/eval_closed_loop.py
scripts/research/configs/tinynav_*.yaml
~~~

### 训练控制

- 使用 mixed precision。
- 保存 exact config、git commit、dataset manifest hash。
- 用 optimizer steps 而不是 epoch 对齐不同 mixture。
- 固定图像 augment 和数据采样 seed。
- 每个实验至少三次训练 seed。
- 先做 5% 数据/短 step pilot，再扩展。

## 6. 第五阶段：闭环 benchmark 重建

当前 MuJoCo easy/medium/hard 成功率饱和，不适合新论文主实验。

需要重建：

1. 20–50 个 procedural scenes 或 scene variants。
2. start/goal/obstacle 随机化。
3. 需要转弯、绕障和恢复，不是直线到点。
4. camera pose、motion blur、brightness、latency、frame drop 扰动。
5. 固定 scene seeds，并划分 dev/test。
6. 不使用 ground-truth route stabilizer 帮助策略。
7. 保存每次 rollout 的完整 config、trajectory、collision 和 timing。

最低统计：

~~~
3 training seeds
x 20 evaluation seeds
x 3 core methods
~~~

如果计算不足，先减少方法数量，不要先减少 evaluation seeds。

## 7. 4090 预算策略

单卡可行，但瓶颈未必是显存，而是数据 IO、baseline 数量和闭环仿真。

优先级：

1. frozen/compact encoder pilot。
2. 统一 baseline。
3. 训练小 generative head。
4. 只在主结果成立后扩大数据和模型。

不建议首轮：

- 1B 级 pixel world model。
- 大 VLM fine-tuning。
- 大规模 IsaacLab online imitation。
- DPPO/GRPO。
- 10 个 encoder sweep。

## 8. 里程碑与止损

### M0：数据（第 1–4 周）

通过条件：

- 至少 3 个 processed datasets。
- manifest 和 split audit 通过。
- 无明显轨迹泄漏。

失败处理：

- 若只能获得 1–2 个数据集，停止 cross-dataset claim，改做 corruption/scale benchmark。

### M1：baseline（第 5–8 周）

通过条件：

- single/multi-dataset NoMaD 和 deterministic baseline 均可复现。
- 三个 seed 的训练方差可接受。

失败处理：

- 优先修数据和环境，不开始新模型。

### M2：TinyNavBrain offline（第 9–14 周）

通过条件：

- held-out dataset 至少两个指标稳定改善。
- 参数量/训练 step/NFE 公平。
- 改善超过 seed variance。

失败处理：

- 如果仅 latency 改善，降级为 efficiency study。
- 如果仅 IID 改善，不能写 cross-domain generalization。

### M3：closed-loop（第 15–20 周）

通过条件：

- collision/SPL/SR 至少一项稳定优于强 baseline。
- failure analysis 与 offline diagnostic 一致。

失败处理：

- 若 offline 提升不能转化为闭环，论文暂缓。

### M4：deployment and paper（第 21–24 周）

通过条件：

- Jetson 或目标设备 timing 完整。
- 主要图表和代码可复现。
- RA-L 三条贡献都由实验直接支持。

## 9. 第一条实际命令之前

开始训练前，必须先完成：

1. 选择并核验 2–4 个外部数据集。
2. 估算磁盘和下载时间。
3. 修复/建立可复现 conda 环境。
4. 确认多数据集 sampler 不会被大数据集完全主导。
5. 为每个数据集生成可视化 sanity batch。

未完成这些步骤时，不建议写 TinyNavBrain 训练代码。
