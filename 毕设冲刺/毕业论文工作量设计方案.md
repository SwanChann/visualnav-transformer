## 3. 相关领域研究现状调研

## 3.1 视觉导航研究主线

视觉导航的发展可以概括为三条演进链路：

| 阶段 | 代表方向 | 特点 |
|---|---|---|
| 传统视觉导航 | 地图、定位、规划、局部避障 | 依赖显式建图与模块化系统 |
| 学习型视觉导航 | GNM、ViNT、NoMaD | 从视觉输入直接学习导航策略或 waypoint |
| 基础模型/具身化视觉导航 | VLN 基础模型、VLA、E-MLLM、网页视频预训练 | 强调多模态理解、跨任务泛化、跨形态部署 |

对你的毕设最重要的不是把整个领域全讲一遍，而是把以下逻辑讲清楚：

1. 传统方法强在稳定性，但弱在开放环境泛化。
2. 学习型方法强在端到端和数据驱动泛化，但弱在可解释性与部署稳定性。
3. 基础模型时代开始强调“统一表征 + 多模态输入 + 跨机器人形态”，这正好给你的足式迁移工作提供背景支撑。

## 3.2 GNM → ViNT → NoMaD：你的毕设最相关技术脉络

### GNM

GNM 提出“用跨机器人数据训练通用导航模型”，核心思想是把动作抽象到形态无关的导航表示上，而不是绑定到底层电机控制。  
来源：GNM, arXiv:2210.03370（2022-10-07 提交，2023 版本）  
链接：https://arxiv.org/abs/2210.03370

### ViNT

ViNT 进一步把视觉导航推向“基础模型”思路，强调用大规模、多场景数据训练可迁移的视觉导航表示。  
来源：ViNT, arXiv:2306.14846（2023-06-26 提交，2023-10-24 修订）  
链接：https://arxiv.org/abs/2306.14846

### NoMaD

NoMaD 把扩散策略引入视觉导航，通过 goal masking 把“目标导航”和“无目标探索”统一到同一个扩散策略中。  
来源：NoMaD, arXiv:2310.07896（2023-10-11 提交）  
链接：https://arxiv.org/abs/2310.07896

对你的毕设而言，这三篇工作可以被组织成如下逻辑：

- GNM 证明了跨机器人数据和动作抽象的价值。
- ViNT 证明了视觉导航可以走向基础模型化。
- NoMaD 证明了扩散策略在导航与探索统一建模上的优势。

你的工作不是重新发明一套导航模型，而是继续追问：

**NoMaD 这样一个在轮式平台验证成功的扩散视觉导航策略，能否通过合理优化与系统重构，被迁移到足式机器人部署场景？**

这正是一个成立且合理的毕业设计问题。

## 3.3 VLN 研究现状与你课题的关系

VLN 的核心任务是“视觉 + 语言指令 → 导航行为”，已经从早期 R2R 风格室内导航发展到基础模型时代。  
来源：Vision-and-Language Navigation Today and Tomorrow: A Survey in the Era of Foundation Models, arXiv:2407.07035（2024-07-09 提交，2024-12-29 修订）  
链接：https://arxiv.org/abs/2407.07035

这个方向对你课题的意义在于：

1. 它说明视觉导航正在从“纯图像目标”扩展到“语言、地图、对话、多模态目标”。
2. 它说明当前研究越来越强调高层规划、推理、记忆和统一代理。
3. 它也提醒你：你的毕设主任务不是 VLN 本身，而是**图像目标视觉导航在足式机器人的应用与系统重构**。

所以，VLN 在你的论文中应该作为“相关背景和发展趋势”出现，而不应该把主体工作误写成“做语言导航”。

## 3.4 具身智能研究现状

具身智能当前的主流方向已经从单任务感知控制，转向“基础模型 + 多模态 + 统一代理”。

代表性综述：

1. A Survey on Robotics with Foundation Models: toward Embodied AI, arXiv:2402.02385  
链接：https://arxiv.org/abs/2402.02385

2. Exploring Embodied Multimodal Large Models: Development, Datasets, and Future Directions, arXiv:2502.15336  
链接：https://arxiv.org/abs/2502.15336

这些研究共同说明：

- 具身智能的目标是开放环境中的泛化感知、推理、决策与控制。
- 当前最大瓶颈不只是模型能力，还包括数据、实时性、系统集成和 sim-to-real。
- 导航是具身智能的基础能力之一，不是孤立问题。

对你的毕设而言，最重要的启发是：

**足式机器人视觉导航不是一个“换个底盘跑同样代码”的问题，而是一个具身系统重构问题。**

## 3.5 足式机器人视觉导航研究现状

你的工作如果要站得住，必须明确：  
“把 NoMaD 用到足式机器人”并不是整个领域里从未有人做过足式导航，而是**NoMaD 这类扩散视觉导航策略尚未被系统性地迁移到足式部署问题上。**

这点必须严格表述，避免答辩时被反驳。

### 已有代表工作

#### VP-Nav

Coupling Vision and Proprioception for Navigation of Legged Robots, arXiv:2112.02094  
链接：https://arxiv.org/abs/2112.02094

该工作说明：

- 足式机器人比轮式平台更适合复杂地形与障碍环境；
- 但高层导航必须考虑低层步态能力；
- 单纯视觉不够，本体感知信息对于安全部署很关键。

#### NaVILA

NaVILA: Legged Robot Vision-Language-Action Model for Navigation, arXiv:2412.04453  
链接：https://arxiv.org/abs/2412.04453

该工作说明：

- 足式机器人导航已经进入 VLA 和双层控制框架阶段；
- 高层输出不直接是关节，而是中层动作语义；
- 真正难点在“高层导航输出如何被低层步态策略稳定执行”。

### 对你课题的直接结论

1. “足式机器人视觉导航”本身不是空白。
2. “扩散策略 NoMaD 在足式部署场景下的系统性适配研究”仍有空间。
3. 因此你的创新表述不能写成“首次做足式视觉导航”，而应写成：

**首次针对 NoMaD 扩散视觉导航框架开展面向足式部署场景的系统性适配、优化与跨形态验证研究。**

## 3.6 当前研究中的共性问题

综合上述论文与综述，当前研究主要存在以下问题：

| 问题 | 具体表现 | 对你课题的启发 |
|---|---|---|
| 推理实时性不足 | 扩散模型和大模型推理慢 | DDIM 加速是合理切入点 |
| 跨形态迁移缺少系统接口 | 高层导航与低层步态耦合复杂 | 必须做分层系统设计 |
| 视觉表示泛化不够 | 相机高度、视角、地形变化带来 domain gap | DINOv2 升级有意义 |
| 纯视觉部署脆弱 | 动态模糊、抖动、透明障碍、滑移 | 足式系统需补安全与鲁棒性设计 |
| 工程可复现性不足 | 环境、路径、依赖、权重配置分散 | 需要系统重构与配置统一 |
| 评估体系不统一 | 学术指标与部署指标脱节 | 论文中要设计双层评价体系 |

## 3.7 未来发展方向

根据 2024-2025 年综述与新工作，未来方向主要集中在：

1. 统一具身代理：从单一导航器走向多模态统一行动体。
2. 更多模态融合：视觉、语言、深度、IMU、本体感知联合建模。
3. Web-scale 数据利用：如 CityWalker 用海量网页视频学习导航。
4. 实时性与边缘部署：模型压缩、蒸馏、快速采样、异构推理。
5. 跨形态与跨场景泛化：轮式、足式、双足、人形机器人间迁移。
6. sim-to-real 闭环：不仅在仿真里成功，更能在真实机器人上稳定运行。

你的毕设最适合对接其中三条：

- 实时性优化
- 跨形态迁移
- 系统级部署可行性

## 5.3 第四章：面向足式部署的 NoMaD 优化方法研究

### 章节定位

这一章是整个毕设最容易形成“方法贡献 + 实验支撑”的核心章节，应作为主体工作量最大的一章。

### 优化方向设计

建议把你的优化工作明确分成三个子模块：

| 子模块 | 目标 | 当前状态 |
|---|---|---|
| 采样加速优化 | 解决扩散推理实时性不足 | DDIM 已完成 |
| 条件引导优化 | 增强目标导向性与轨迹可控性 | CFG 已完成 |
| 表征升级优化 | 提升跨视角、跨形态视觉泛化能力 | DINOv2 已起步 |

### 子模块一：DDIM 加速采样

#### 研究动机

足式机器人高层导航对实时性要求高于单纯离线推理。扩散策略若推理太慢，系统难以稳定闭环。

#### 你的工作定位

基于 DDIM 对 NoMaD 的扩散采样过程进行加速，对比不同去噪步数下的时间开销与轨迹质量。

#### 现有结果可直接使用

| 配置 | 时间 |
|---|---|
| DDPM-10 | 29.47 ms |
| DDIM-5 | 15.16 ms |
| DDIM-3 | 7.87 ms |
| DDIM-2 | 6.24 ms |
| DDIM-1 | 3.00 ms，但质量明显退化 |

#### 建议结论

`DDIM-5` 作为默认部署配置最稳妥；`DDIM-2` 可作为极限实时方案；`DDIM-1` 不建议采用。

### 子模块二：Classifier-Free Guidance 目标引导增强

#### 研究动机

NoMaD 的 goal masking 机制天然提供了“有条件 / 无条件”两类特征路径，因此可以引入 CFG，在不改训练目标的前提下增强目标导向性。

#### 你的工作定位

将 CFG 从生成建模思想迁移到导航轨迹采样过程中，研究 guidance scale 对轨迹多样性、位移趋势和推理开销的影响。

#### 现有结果可直接使用

| `w` | Diversity | Mean Disp. | Time(ms) |
|---|---:|---:|---:|
| -1.0 | 0.0259 | 0.0735 | 267.3 |
| 0.0 | 0.0201 | 0.0333 | 30.9 |
| 0.5 | 0.0220 | 0.0448 | 47.4 |
| 1.0 | 0.0265 | 0.0371 | 46.8 |
| 2.0 | 0.0236 | 0.0637 | 46.8 |
| 4.0 | 0.0139 | 0.0929 | 46.6 |

#### 建议结论

- `w=1.0` 可作为平衡点；
- 中等引导强度有利于增强目标导向性；
- 过强引导会损失轨迹多样性；
- CFG 会带来额外推理开销，但仍在可接受范围内。

### 子模块三：DINOv2 视觉编码器升级

#### 研究动机

原始 NoMaD 使用 EfficientNet-B0，适合基线复现，但对于相机高度变化、视角变化、跨平台视觉差异，表征能力可能不足。DINOv2 的无监督视觉特征更适合部署导向迁移分析。

#### 你的工作定位

**开展视觉编码器升级探索，验证更强基础视觉表征对 NoMaD 在跨形态部署场景中的潜在价值。**

- 作为“优化探索的重要组成”
- 作为“足式迁移的视觉基础准备”

## 5.4 第五章：轮式到足式的跨形态导航系统设计与可行性验证

### 章节定位

这是你的“问题回答章”，必须正面回答：

1. 为什么轮式导航要迁移到足式机器人？
2. 迁移时系统实现上哪里不同？
3. NoMaD 为什么适合做这种迁移？
4. 你的系统设计方案是什么？

### 这一章一定不能写成纯概念讨论

必须至少包含以下三类内容：

| 类型 | 内容 |
|---|---|
| 需求层 | 为什么足式平台值得做视觉导航 |
| 结构层 | 高层导航与低层步态如何解耦 |
| 验证层 | 至少给出仿真或接口级验证 |

### 建议的核心逻辑

#### 第一部分：轮式与足式的差异分析

| 维度 | 轮式平台 | 足式平台 |
|---|---|---|
| 地形适应性 | 平坦地面更优 | 更适合台阶、坡面、碎石、门槛 |
| 控制方式 | `cmd_vel` 即可直接执行 | 需经速度层、步态层、关节层 |
| 相机稳定性 | 画面更平稳 | 视角抖动、机身周期起伏更明显 |
| 实时性要求 | 中等 | 更高 |
| 安全边界 | 较清晰 | 失稳、打滑、跌倒风险更高 |

#### 第二部分：为什么 NoMaD 有迁移潜力

因为 NoMaD 输出的是**相对 waypoint**，而不是直接输出底层关节动作。

这意味着它本质上回答的是：

**“往哪里走”**

而不是：

**“腿怎么摆”**

这为跨形态迁移提供了天然接口。

#### 第三部分：你的系统设计方案

建议采用标准分层架构：

```text
视觉观测层
  -> 图像采集、预处理、目标图像输入

高层导航策略层
  -> NoMaD / 优化后的 NoMaD
  -> 输出相对 waypoint 轨迹

中间动作接口层
  -> waypoint 选择
  -> waypoint -> velocity 转换
  -> 约束过滤与安全裁剪

足式运动控制层
  -> 速度命令 -> 步态策略 / locomotion policy
  -> 步态执行

反馈评估层
  -> 成功率、轨迹偏差、实时频率、稳定性指标
```

| 工作项 | 作用 | 是否建议纳入核心 |
|---|---|---|
| Lite3 或 Husky/Lite3 对比仿真 | 证明高层 waypoint 迁移接口合理 | 建议纳入核心 |
| 轮式到足式动作接口分析 | 回答“实现上哪里不一样” | 必做 |
| 安全约束设计 | 体现足式部署特殊性 | 建议纳入核心 |
| 步态抖动实验 | 体现视觉扰动问题 | 可选补强 |

因为你已经明确说明这部分没做，而当前已有的主线工作已经足以支撑三章主体。  
如果为了补齐而硬做，很可能分散主线、压缩核心成果。

- 主线聚焦：基线复现 + NoMaD 优化 + 跨形态系统设计
- 可选增强：步态抖动鲁棒性、综合消融、实时摄像头演示

### 本章核心贡献表述

**针对 NoMaD 原始框架仅在轮式平台验证的问题，提出面向足式机器人部署场景的跨形态导航系统设计方案，通过高层 waypoint 抽象、中间速度接口层以及低层步态执行层的分层解耦，分析并验证视觉导航策略迁移到足式机器人上的可行性。**

## 7. NoMaD 优化方案设计

## 7.1 总体优化目标

你的优化方案不应写成“为了提升指标而调参”，而应明确为：

**为了使 NoMaD 更适合足式机器人部署场景，从实时性、可控性、视觉泛化性和工程可部署性四个维度进行系统优化。**

## 7.2 四维优化框架

| 维度 | 对应问题 | 对应方案 |
|---|---|---|
| 实时性 | 扩散推理慢，闭环频率不足 | DDIM 加速 |

| 泛化性 | 视角变化和跨形态视觉差异 | DINOv2 编码器升级 |
| 工程性 | 路径硬编码、环境耦合强 | 配置重构与相对路径化 |

## 7.3 推荐的最终部署配置

如果要在论文中给出一个“建议部署版本”，推荐组合为：

**NoMaD + DDIM-5 + CFG(`w=1.0`) + 相对路径配置重构**

理由：

1. DDIM-5 速度和质量平衡最好；
2. CFG `w=1.0` 引导增强效果较稳；
3. DINOv2 可以作为增强探索，但在结果不充分前不建议当作唯一主部署版本；
4. 工程配置重构是必须完成的，不然系统可复现性不够。

## 7.4 DINOv2 的定位建议

论文中建议将 DINOv2 定位为：

- 一个“重要的增强探索”
- 一个“针对跨形态视觉差异的潜在升级方向”

这比强行把它写成“核心确定结论”更稳健。

## 8. 足式导航系统重新分析与设计方案

## 8.1 设计目标

重新设计后的系统不是简单替换底盘，而是要满足以下目标：

1. 高层导航策略与低层步态控制解耦；
2. 支持轮式与足式平台共享同一高层导航输出；
3. 支持训练环境与部署环境分离；
4. 支持后续加入 IMU、本体感知、安全约束等模块。

## 8.2 推荐系统架构

### 第一层：数据与配置层

负责：

- 数据路径管理
- 权重路径管理
- Ubuntu 20.04/22.04 双环境配置
- YAML 配置统一

建议改造目标：

- 所有实验脚本统一从相对路径或环境变量读取根目录
- 数据集路径、权重路径、输出路径全部配置化

### 第二层：模型推理层

负责：

- NoMaD 推理
- DDPM/DDIM 调度切换
- CFG 开关
- 视觉编码器切换

### 第三层：动作接口层

负责：

- 轨迹样本选择
- `waypoint -> velocity`
- 安全裁剪与限幅
- 为足式控制器提供统一动作接口

这是轮式到足式迁移最关键的一层。

### 第四层：平台执行层

负责：

- 轮式平台：`cmd_vel`
- 足式平台：速度命令 -> locomotion controller -> gait execution

### 第五层：反馈评估层

负责：

- 推理频率
- 轨迹偏差
- 任务成功率
- 稳定性或可通过性指标

## 8.3 轮式到足式实现差异的答辩表述

建议用下面这段逻辑回答：

> 轮式平台中，高层导航输出的速度命令可以直接由底盘执行；而足式机器人中，高层导航输出必须先经过中间动作接口层转换为可被低层步态控制器接受的速度或目标运动指令，再由步态控制器生成关节级执行结果。因此，从轮式迁移到足式，不是替换控制节点这么简单，而是需要重构“导航策略输出到平台执行”的中间层与约束机制。

这段话很关键，建议你后续答辩时反复使用。

## 8.4 足式系统中建议增加的安全约束

为了体现系统设计深度，建议在方案中加入以下约束项：

| 约束 | 作用 |
|---|---|
| 最大线速度约束 | 防止高层输出过快导致步态不稳 |
| 最大角速度约束 | 防止急转导致失稳 |
| waypoint 曲率约束 | 防止轨迹拐点过陡 |
| 低速保守模式 | 在狭窄区域或不确定条件下降速 |

即使这些约束最终只做到设计分析或仿真示意，也足够体现系统设计能力。
