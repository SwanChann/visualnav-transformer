# 视觉编码器升级完整教程

本文档单独说明 NoMaD 视觉编码器升级实验的完整工作流。目标是在保持 NoMaD 导航头、距离预测头、扩散策略结构基本一致的前提下，将 baseline 的 EfficientNet-B0 视觉编码器替换为 DINOv2、ConvNeXt、ResNet 等不同视觉表征网络，并通过统一训练、统一测试和多次重复实验分析不同视觉编码器对视觉导航性能的影响。

## 1. 视觉编码器如何替换

NoMaD 的整体链路可以拆成三部分：图像输入、视觉条件编码、扩散式 waypoint 生成。视觉编码器升级只改第二部分，也就是把当前观测图像序列和目标图像编码成同一个维度的条件向量，后面的距离预测网络和扩散 waypoint 预测网络尽量保持不变。这样做的好处是论文实验更干净：性能变化主要来自视觉表征能力，而不是整个策略网络一起变化。

替换时需要保证四个接口一致。第一，输入图像尺寸要和 backbone 匹配，例如 DINOv2-Small 使用 patch14，推荐输入为 98x98；ConvNeXt-Tiny 和 ResNet-50 在本实验中统一使用 96x96。第二，backbone 输出维度要经过 projection 映射到 NoMaD 使用的 `encoding_size=256`。第三，观测帧和目标帧都要经过同一种视觉编码器，避免观测特征和目标特征处在不同表征空间。第四，goal mask 机制不应被删除，因为它决定模型在导航模式和探索模式之间的条件切换方式。第五，DINOv2 属于 ViT 类模型，预训练权重默认匹配 token pooling；因此代码中对 `dinov2_small` 使用 `global_pool="token"`，而 ConvNeXt 和 ResNet 继续使用 `global_pool="avg"`。

本课题建议将视觉编码器分成两类。第一类是论文正式对比编码器：`efficientnet_b0`、`dinov2_small`、`convnext_tiny`、`resnet50`。其中 `efficientnet_b0` 作为原始 NoMaD baseline，主要使用已有权重进行对照；其余三个通过统一 backbone suite 训练。第二类是扩展候选编码器：`mobilenetv3_large`、`efficientnetv2_s`、`vit_small_patch16_224`、`clip_vit_b16`。这些可以放在后续扩展工作中，但不建议一开始全部纳入正式实验，否则训练成本和论文变量会明显增加。

本仓库中与视觉编码器替换相关的代码路径如下。

| 功能 | 路径 |
| --- | --- |
| 原始 NoMaD EfficientNet-B0 视觉编码器 | `train/vint_train/models/nomad/nomad_vint.py` |
| DINOv2 单独实现 | `scripts/models/nomad_vint_dinov2.py` |
| 多视觉编码器统一模型入口 | `scripts/models/nomad_vint_backbone_suite.py` |
| 多视觉编码器统一训练入口 | `scripts/training/train_backbone_suite.py` |
| 多随机种子训练启动脚本 | `scripts/training/run_encoder_seed_sweep.py` |
| 预训练权重下载脚本 | `scripts/models/download_encoder_weights.py` |
| 多编码器离线对比实验脚本 | `scripts/experiments/encoder_comparison_experiment.py` |
| DINOv2-Small 配置模板 | `scripts/configs/vision_encoder/nomad_encoder_dinov2_small.yaml` |
| ConvNeXt-Tiny 配置模板 | `scripts/configs/vision_encoder/nomad_encoder_convnext_tiny.yaml` |
| ResNet-50 配置模板 | `scripts/configs/vision_encoder/nomad_encoder_resnet50.yaml` |

## 2. Ubuntu 22.04 训练环境步骤

第一步，创建训练环境。建议使用 Ubuntu 22.04、NVIDIA GPU、CUDA 11.8 或 CUDA 12.1。Python 版本建议使用 3.8 或 3.9，优先保持和原 NoMaD 工程兼容。

```bash
conda create -n nomad_encoder python=3.8 -y
conda activate nomad_encoder
```

第二步，安装 PyTorch。下面命令适合 CUDA 12.1；如果本机 CUDA 环境是 11.8，将 `cu121` 改成 `cu118`。

```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
```

第三步，安装工程依赖。需要在仓库根目录执行。

```bash
cd ~/visualnav-transformer
pip install -r scripts/requirements.txt
pip install timm diffusers warmup-scheduler wandb matplotlib pandas pyyaml
cd train
pip install -e .
cd ..
```

第四步，准备数据集。默认配置使用 `nomad_dataset/go_stanford`，数据划分路径使用 `train/vint_train/data/data_splits/go_stanford/train/` 和 `train/vint_train/data/data_splits/go_stanford/test/`。训练前要检查三个位置是否存在：数据根目录、训练 split、测试 split。如果路径不一致，只修改 YAML 配置中的 `datasets.go_stanford.data_folder`、`datasets.go_stanford.train` 和 `datasets.go_stanford.test`，不要在训练脚本里硬编码路径。

第五步，下载或预缓存视觉编码器权重。`timm` 在第一次创建模型时会自动下载权重，但正式训练前建议主动下载，避免训练过程中因为网络问题中断。

```bash
python scripts/models/download_encoder_weights.py --backbone all --cache-dir ~/.cache/nomad_encoder
```

如果要验证权重和网络结构是否能正常前向传播，可以追加 `--verify-forward`。如果只想查看会下载哪些模型，可以追加 `--dry-run`。

## 3. 训练代码与配置使用方法

正式训练前建议先做一次短实验，把对应 YAML 中的 `epochs` 临时改成 `1`，确认数据、模型、GPU、日志路径全部正常。确认无误后再改回 `20` 进行验证训练；如果验证曲线稳定，再扩展到 `80` 或 `100` epoch 作为论文正式结果。

DINOv2-Small 训练命令如下。

```bash
cd ~/visualnav-transformer
python scripts/training/train_backbone_suite.py \
  --config "$(pwd)/scripts/configs/vision_encoder/nomad_encoder_dinov2_small.yaml" \
  --backbone dinov2_small \
  --freeze-backbone \
  --pretrained-backbone
```

ConvNeXt-Tiny 训练命令如下。

```bash
cd ~/visualnav-transformer
python scripts/training/train_backbone_suite.py \
  --config "$(pwd)/scripts/configs/vision_encoder/nomad_encoder_convnext_tiny.yaml" \
  --backbone convnext_tiny \
  --freeze-backbone \
  --pretrained-backbone
```

ResNet-50 训练命令如下。

```bash
cd ~/visualnav-transformer
python scripts/training/train_backbone_suite.py \
  --config "$(pwd)/scripts/configs/vision_encoder/nomad_encoder_resnet50.yaml" \
  --backbone resnet50 \
  --freeze-backbone \
  --pretrained-backbone
```

注意：当前训练入口会把相对配置路径解析到 `train/` 目录下，因此上面的命令直接使用 `$(pwd)/...` 生成绝对路径，避免路径被错误拼接。如果手动传相对路径，需要确认它是从 `train/` 目录再拼接后仍能找到的路径。

多随机种子实验建议使用统一启动脚本。下面命令会为每个 seed 生成独立 YAML 配置，并串行运行训练，避免多个任务争抢同一块 GPU。

```bash
python scripts/training/run_encoder_seed_sweep.py \
  --base-config scripts/configs/vision_encoder/nomad_encoder_dinov2_small.yaml \
  --backbone dinov2_small \
  --seeds 0 1 2 \
  --freeze-backbone \
  --pretrained-backbone
```

训练输出默认保存到 `train/logs/nomad-backbone-suite/`。每个 run 内通常会保存 `config.yaml`、`latest.pth`、按 epoch 编号的 checkpoint，以及可能存在的 `ema_latest.pth`。论文实验中应固定 checkpoint 选择规则，例如统一使用验证损失最低的 epoch，或者统一使用 `latest.pth`，不能对不同编码器采用不同挑选标准。

如果显存不足，优先把 `batch_size` 和 `eval_batch_size` 从 `64` 降到 `32`，再考虑降低 `num_workers`。如果训练不稳定，优先保持 backbone 冻结，只训练 projection、注意力融合层和导航头；只有当冻结 backbone 的结果已经稳定后，才做不冻结 backbone 的微调对比。

## 4. 不同视觉编码器性能评估实验设计

实验目标不是简单比较某一次训练谁的结果更好，而是回答三个更科学的问题：第一，不同视觉编码器是否稳定提升 waypoint 预测质量；第二，提升是否能跨测试路线、跨距离区间泛化；第三，提升是否值得付出更高推理延迟和显存占用。

正式实验建议采用如下变量控制。

| 项目 | 设计 |
| --- | --- |
| 自变量 | 视觉编码器类型：EfficientNet-B0、DINOv2-Small、ConvNeXt-Tiny、ResNet-50 |
| 控制变量 | 数据集划分、context size、goal mask 概率、扩散步数、训练 epoch、batch size、优化器、学习率 |
| 重复实验 | 每个编码器至少 3 个随机种子，条件允许时使用 5 个随机种子 |
| 测试集 | 至少使用 GoStanford test split；如果有自采集或 MuJoCo 数据，可增加第二、第三测试集 |
| 距离分组 | short、medium、long 三组目标距离，避免只在短距离目标上得出结论 |
| 推理重复 | 每个 case 至少重复 8 次 diffusion sampling，用均值和方差衡量随机采样稳定性 |

离线评估使用 `scripts/experiments/encoder_comparison_experiment.py`。命令示例如下，其中 checkpoint 路径需要替换成实际训练得到的 `latest.pth` 或选定 epoch 权重。

```bash
python scripts/experiments/encoder_comparison_experiment.py \
  --model-spec efficientnet_b0=deployment/model_weights/nomad/nomad.pth \
  --model-spec dinov2_small=train/logs/nomad-backbone-suite/nomad_dinov2_small_xxx/latest.pth \
  --model-spec convnext_tiny=train/logs/nomad-backbone-suite/nomad_convnext_tiny_xxx/latest.pth \
  --model-spec resnet50=train/logs/nomad-backbone-suite/nomad_resnet50_xxx/latest.pth \
  --dataset-root nomad_dataset/go_stanford \
  --suite-offsets short:8,medium:16,long:24 \
  --cases-per-suite 8 \
  --num-runs 8 \
  --num-samples 8 \
  --scheduler ddim \
  --num-steps 5
```

该脚本会输出 case 级记录、按模型聚合的整体统计、按测试集和距离分组聚合的统计表，以及可视化图。输出目录位于 `results/day4/encoder_comparison_experiment_*`。论文中建议至少报告以下指标：平均推理延迟、距离预测均值、轨迹长度、终点距离、前向进展、横向偏移、轨迹平滑度、采样多样性。

为了保证结论可靠，统计分析建议采用三层汇总。第一层是 case 级别，保留每个测试样本的原始结果，便于后续复查。第二层是 suite 级别，分别报告 short、medium、long 的均值和标准差，判断模型是否只在某类距离上有效。第三层是整体级别，对每个编码器报告均值、标准差和 95% 置信区间。如果要比较两个编码器是否有显著差异，优先使用相同 case 上的 paired bootstrap 或 paired t-test，而不是直接比较两个独立均值。

如果要进一步连接到机器人平台实验，可以在离线评估后增加 MuJoCo 导航实验。建议固定同一组 topomap、同一批起点和终点、同一套底层控制器参数，只替换高层 NoMaD checkpoint。平台实验指标包括成功率、到达时间、路径长度、碰撞次数、恢复次数、平均速度、控制抖动。这样可以回答一个更工程化的问题：视觉编码器提升是否真的能传递到 Lite3 或 Tron1 的闭环导航表现。

## 5. 论文写作建议

论文中不要把视觉编码器升级写成“换了一个网络所以效果更好”，而要写成“在统一 NoMaD 导航框架下研究视觉表征能力对目标导航策略的影响”。第二章可以介绍不同视觉编码器的表征特点，第三章或第四章说明替换接口，实验章再比较训练曲线、离线 waypoint 指标和仿真闭环指标。

推荐结论表述方式如下：如果 DINOv2-Small 在长距离目标和复杂场景上表现更好，可以解释为自监督视觉表征增强了场景语义和视角变化鲁棒性；如果 ConvNeXt-Tiny 延迟更低且效果接近 DINOv2，可以强调其工程部署优势；如果 ResNet-50 效果稳定但提升有限，可以作为传统 CNN backbone 的稳健对照；如果 EfficientNet-B0 推理最快但泛化较弱，可以作为原始 baseline 的合理位置。

最终提交论文结果时，至少保留四类文件：训练配置快照、checkpoint 路径、评估原始 CSV、汇总表和图。这样即使后续需要复现实验，也能从配置、权重、测试样本和统计结果四个层面追溯。
