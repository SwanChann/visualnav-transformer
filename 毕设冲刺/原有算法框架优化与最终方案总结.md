# 原有算法框架优化与最终方案总结

## 1. 文档定位

本文档用于整理毕业论文中“算法设计与实验”章节的主线：先说明原始 NoMaD 算法框架，再说明 DDIM 加速推理、CFG 引导增强、TTS 推理时搜索和视觉编码器升级四类优化方法之间的关系，最后根据已有实验结果确定当前版本的最终算法方案。

这里的结论只针对当前项目已有证据链成立：离线统计实验、统一推理模块实验、TTS 组合实验、四编码器离线对比和 MuJoCo 闭环验证。真机统计实验尚未完全补齐，因此涉及最终部署时，需要在论文中明确“仿真闭环推荐方案”和“真机最终推荐方案”的证据边界。

## 2. 原始算法框架

原始算法以 NoMaD 为核心，输入为历史 RGB 视觉观察和目标图像，输出为未来局部 waypoint 序列。系统不直接预测底层速度命令，而是学习条件轨迹分布：

```text
history images + goal image -> vision encoder -> condition tokens
condition tokens -> distance head
condition tokens -> diffusion policy head -> waypoint candidates
waypoint candidates -> controller/state machine -> platform action
```

该框架可以分成三层理解：

1. 视觉条件层：由视觉编码器把历史观察和目标图像编码为共享条件特征。
2. 生成策略层：扩散策略头在视觉条件下生成多条候选 waypoint 轨迹。
3. 执行选择层：系统根据距离预测、轨迹筛选或控制接口选择最终轨迹并下发。

因此，论文中介绍优化方案时不应把四个优化写成互不相干的“功能堆叠”，而应放回上述三层结构中：

| 优化方法 | 所在层级 | 主要改变 | 是否改变训练 |
|---|---|---|---|
| DDIM | 生成策略层 | 改变扩散采样调度和去噪步数 | 否 |
| CFG | 生成策略层 | 改变条件引导强度 | 否 |
| TTS | 执行选择层 | 扩展/筛选候选轨迹 | 否 |
| 视觉编码器升级 | 视觉条件层 | 改变条件特征质量和分布 | 是 |

## 3. 四类优化的关系

### 3.1 DDIM、CFG、TTS 的层级关系

DDIM、CFG 和 TTS 都属于推理阶段优化，但它们作用的位置不同。

DDIM 决定“每条候选轨迹如何生成”。它通过减少扩散去噪步数降低时延，是部署端最直接的加速手段。实验表明 DDIM-2 在保持轨迹质量可接受的前提下获得约 4.84 倍加速，而 DDIM-1 已经出现明显轨迹分布偏移，因此不适合作为稳定部署方案。

CFG 决定“生成过程对目标条件有多敏感”。它通过条件预测和无条件预测的线性外推增强目标引导，但会带来接近两倍的噪声网络前向计算成本。已有实验显示 CFG 的边际收益有限，默认不应强行开启；在复杂目标牵引场景中可以作为可调增强项。

TTS 决定“生成出的候选轨迹如何选择”。它不是新的训练方法，也不是新的采样器，而是在已有候选上使用评分函数做推理时搜索。TTS-8 的主要收益来自对默认 8 条候选轨迹的评分筛选，额外时延几乎可忽略；TTS-16 进一步扩展候选池但收益变小；TTS-32 时延明显增加，综合收益下降。

三者最合理的组合顺序是：

```text
DDIM controls sampling speed
CFG controls conditional guidance
TTS selects from generated candidate trajectories
```

因此，论文中应写成“推理层的层级组合优化”，而不是“DDIM + CFG + TTS 三个并列开关”。

### 3.2 视觉编码器升级与前三者的关系

视觉编码器升级和前三个优化并非完全无关，但也不是同一类优化。

前三个方法主要作用在推理阶段，不改变训练后的视觉条件空间；视觉编码器升级会改变历史观察和目标图像的特征表达，进而同时影响距离预测头和扩散策略头。由于 NoMaD 中距离预测头与扩散策略头共享视觉条件特征，因此更换视觉编码器后必须重新训练距离头和轨迹生成头，不能直接把旧头接到新编码器上使用。

它们之间的联系体现在两点：

1. DDIM、CFG、TTS 的效果依赖视觉条件质量。视觉特征越稳定，少步 DDIM 和 TTS 评分越容易保留有效轨迹。
2. 视觉编码器改变条件分布后，最优 DDIM 步数、CFG 权重和 TTS budget 可能发生变化，因此需要做联合实验，而不能只看单项离线指标。

但从工程接口看，它们又是相对独立的：视觉编码器由 `policy_config` 和 `policy_checkpoint` 决定，DDIM/CFG/TTS 由统一推理参数决定。只要模型保持 NoMaD 兼容接口，系统层状态机和平台接口不需要改动。

## 4. 已有实验与结论

### 4.1 DDIM 加速推理

已有实验：DDPM-10、DDIM-10、DDIM-5、DDIM-3、DDIM-2、DDIM-1 六组离线统计，结果位于：

`results/day2/20260410_143136_ddim_stat_experiment`

核心结论：

| 配置 | 主要结果 | 结论 |
|---|---|---|
| DDIM-2 | 约 4.84 倍加速，MSE 可控 | 有效，推荐默认进入闭环 |
| DDIM-3/5 | 加速较保守，质量稳定 | 有效，可作为保守备选 |
| DDIM-1 | 最快但轨迹分布明显异常 | 无效，不推荐部署 |

### 4.2 CFG 引导增强

已有实验：$w\in\{-1,0,0.5,1,2,4\}$ 六组离线统计，以及 DDIM x CFG 联合实验，结果位于：

`results/day3/20260410_143225_cfg_stat_experiment`

`results/day4/20260410_143709_joint_ddim_cfg_experiment`

核心结论：

| 配置 | 主要结果 | 结论 |
|---|---|---|
| CFG=0 | 综合排名靠前，时延最低 | 推荐默认 |
| CFG=0.5/1.0 | 前进性略有改善，但时延显著增加 | 有提升但不明显 |
| CFG>=2 | 偏移和平滑性风险增加 | 谨慎使用 |

### 4.3 TTS 推理时搜索

已有实验：TTS 单因素、DDIM x TTS、CFG x TTS、DDIM x CFG x TTS 组合统计，结果位于：

`results/day4/20260421_140601_tts_stat_experiment`

核心结论：

| 配置 | 主要结果 | 结论 |
|---|---|---|
| TTS-8 | 近乎零额外采样代价，综合评分明显提升 | 有效，推荐默认 |
| TTS-16 | 质量略高但时延约翻倍 | 有提升但边际收益下降 |
| TTS-32 | 轨迹质量不再明显改善，时延明显增大 | 不推荐默认 |

### 4.4 视觉编码器升级

已有实验：EfficientNet-B0、DINOv2-Small、ConvNeXt-Tiny、ResNet-50 四个训练权重的离线统计和 MuJoCo 闭环验证，结果位于：

`results/day4/20260421_151228_encoder_comparison_experiment`

`results/benchmark/20260421_seeded_mujoco_encoder_benchmark`

核心结论：

| 编码器 | 离线表现 | MuJoCo 闭环表现 | 当前结论 |
|---|---|---|---|
| EfficientNet-B0 | 平滑性最好 | 9/9 成功，时延最低 | 当前默认部署编码器 |
| DINOv2-Small | 表现中等 | 9/9 成功，时延高于 baseline | 有潜力，但不是当前默认 |
| ConvNeXt-Tiny | 表现中等 | 9/9 成功，时延高于 baseline | 可作为候选 |
| ResNet-50 | 前进性和多样性高 | 9/9 成功，但时延最高 | 离线积极，部署需谨慎 |

视觉编码器升级已经证明了“可替换、可训练、可接入闭环”，但尚不能证明 DINOv2 或其他编码器在真机上必然优于 EfficientNet-B0。当前论文中最稳妥的表述是：视觉编码器升级建立了多编码器替换与评测框架，ResNet-50 等编码器在离线指标上显示潜力，但最终部署仍以 EfficientNet-B0 为默认安全方案，待真机统计进一步验证。

## 6. 最终算法框架方案

根据当前已有结果，建议论文中给出三层最终方案，而不是只给一个绝对配置。

### 6.1 当前论文默认方案

```text
Vision encoder: EfficientNet-B0
Scheduler: DDIM
DDIM steps: 2
CFG weight: 0.0
TTS budget: 8
TTS top-k: 4
TTS verifier: heuristic
```

选择理由：

1. EfficientNet-B0 在 MuJoCo 闭环中成功率为 9/9，且时延最低。
2. DDIM-2 已经验证约 4.84 倍加速，质量仍可接受。
3. CFG=0 避免额外前向计算，综合排序并未被高 CFG 明显超过。
4. TTS-8 主要使用评分筛选，不增加采样批次数，却能明显提升候选选择质量。

### 6.2 保守稳定方案

```text
Vision encoder: EfficientNet-B0
Scheduler: DDIM
DDIM steps: 3 or 5
CFG weight: 0.0
TTS budget: 8
```

适用场景：论文答辩中需要强调安全稳定，或者真机实验中 DDIM-2 出现偶发轨迹抖动时。

### 6.3 复杂场景增强方案

```text
Vision encoder: EfficientNet-B0 or ResNet-50 candidate
Scheduler: DDIM
DDIM steps: 2
CFG weight: 0.5 or 1.0
TTS budget: 8 or 16
```

适用场景：目标视觉差异较大、局部路径存在分叉、需要更强目标牵引时。该方案不建议作为默认方案，因为 CFG 和 TTS-16 都会增加时延，且真机安全边界尚未充分验证。

## 7. 论文写作建议

第三章建议按以下逻辑组织：

1. 先介绍整体算法框架：视觉编码器、距离预测头、扩散策略头、统一推理接口。
2. 再介绍基线实验：说明原始 DDPM-10 的时延和部署瓶颈。
3. 逐一介绍优化方法：DDIM、CFG、TTS、视觉编码器升级。
4. 每个优化方法都写清楚：原理、实现位置、实验设置、结果、结论。
5. 最后专门设置“优化关系、消融验证与最终方案确定”小节，把四类方法放到同一张表里比较。

论文中必须避免以下说法：

1. 不要说“DINOv2 已经证明优于 baseline”，当前证据不足。
2. 不要说“CFG 一定有效”，更准确是“有边际收益，但默认不开启更稳妥”。
3. 不要说“TTS 越大越好”，当前结果显示 TTS-32 边际收益下降。
4. 不要把 MuJoCo 的路线稳定项当成真机算法优势，它只是仿真域内的闭环保护。

最终表述建议：

> 本文最终采用 EfficientNet-B0 + DDIM-2 + CFG=0 + TTS-8 作为当前默认算法框架。DDIM-2 提供主要推理加速，TTS-8 提供低成本候选筛选，CFG 保留为复杂场景下的可调增强项，视觉编码器升级作为可替换扩展框架保留。该方案在现有离线统计和 MuJoCo 闭环验证中具有最稳妥的速度、质量和部署可行性折中；后续真机统计实验将进一步检验编码器升级与 CFG/TTS 组合的最终部署收益。
