## 2.1 视觉导航的基本概念和原理

### 2.1.1 视觉导航的任务定义

视觉导航是指机器人以相机采集到的图像为主要感知输入，完成目标定位、路径选择和运动控制的过程。  
从任务形式上看，视觉导航常见的目标定义方式包括：

1. Point-goal navigation  
   目标由相对坐标或几何位置给出，机器人需要根据当前位置与目标位置关系完成导航。

2. Image-goal navigation  
   目标由一张目标图像给出，机器人通过比较当前观测与目标观测之间的视觉差异，逐步接近目标位置。

3. Topological navigation  
   环境被抽象为一组按时间或空间顺序组织的节点图像，机器人需要在当前观测与拓扑节点之间完成匹配，再朝局部子目标前进。

4. Exploration  
   机器人不依赖明确目标图像，而是根据当前观测生成探索性动作，在未知环境中主动移动。

本课题使用的是 **image-goal navigation + topological navigation** 的组合形式。  
在部署阶段，目标通常不是直接的全局坐标，而是一张或一组拓扑图节点图像；NoMaD 通过比较当前观测和目标观测来完成局部导航决策。

### 2.1.2 视觉导航系统的一般结构

视觉导航系统通常由以下几个部分组成：

1. Perception  
   通过单目或多目相机获取当前图像，完成裁剪、缩放、归一化等预处理。

2. Representation  
   将当前观测、历史观测以及目标图像编码为适合导航决策的特征表示。

3. Decision  
   根据视觉特征预测局部路径点、子目标、速度指令或离散动作。

4. Control  
   将高层输出转换为机器人底层可执行的速度命令、底盘控制指令或步态控制输入。

5. Feedback  
   根据任务是否到达目标、是否偏航、是否卡住、是否失稳等反馈信息进行修正。

对于传统模块化系统，上述过程通常分别由定位、建图、规划和控制模块完成；  
对于学习型方法，上述多个阶段会被压缩到统一模型中，通过端到端或半端到端方式直接输出中间导航表示或动作。

### 2.1.3 视觉导航的主要技术路线

当前视觉导航大致可以分为三条路线：

1. 传统模块化视觉导航  
   依赖显式定位、建图和路径规划，优点是可解释性强，缺点是对感知误差和环境变化比较敏感。

2. 学习型视觉导航  
   以 GNM、ViNT、NoMaD 为代表，直接从视觉输入学习导航策略或 waypoint 表示，更适合处理复杂变化场景。

3. 基础模型驱动的具身导航  
   结合视觉、语言、地图、动作等多模态输入，强调跨任务泛化、跨场景迁移和统一具身智能代理。

本课题主要属于第二类，同时吸收第三类中的“统一表示”和“跨平台迁移”思想。

## 2.2 视觉导航在足式机器人上的应用现状

### 2.2.1 足式机器人为什么需要视觉导航

相比轮式平台，足式机器人更适合台阶、坡面、碎石地、门槛和非结构化地形。  
但足式平台在复杂环境中更依赖高层感知与局部决策，否则即使低层步态能力很强，也很难安全地到达目标位置。

视觉导航对足式机器人的意义主要体现在：

1. 扩大可通行环境范围。
2. 弥补纯遥操作在复杂场景中的效率不足。
3. 让高层导航与低层步态形成分层协同。
4. 为具身探索、巡检和自主移动提供基础能力。

### 2.2.2 足式机器人视觉导航的代表工作

#### 1. Vision + Proprioception 路线

代表工作之一是 *Coupling Vision and Proprioception for Navigation of Legged Robots*。  
这一方向强调：对于足式机器人，仅依赖视觉往往不够，机器人本体的速度、姿态、接触状态和稳定性信息同样关键。  
这说明足式导航与轮式导航的差别，不只是在感知输入上，更在于高层导航输出必须适配低层运动控制能力。

论文链接：<https://arxiv.org/abs/2112.02094>

#### 2. Vision-Language-Action / Foundation Model 路线

近年来，足式机器人导航逐步与视觉语言动作模型结合，例如 NaVILA 将高层导航能力与足式平台的执行能力进一步结合。  
这一类方法通常不直接输出关节动作，而是输出中层语义动作、局部目标或路径指令，再交由底层控制器执行。

论文链接：<https://arxiv.org/abs/2412.04453>

### 2.2.3 足式导航研究的阶段性特点

从研究现状看，足式机器人视觉导航大致经历了三个阶段：

1. 传统规划 + 足式运动控制耦合阶段。  
   重点在于让足式平台能够按照规划路径稳定行走。

2. 视觉学习导航阶段。  
   重点在于通过图像学习局部路径、局部目标和控制策略。

3. 多模态与统一具身阶段。  
   重点在于把视觉、语言、本体感知和大模型推理联合起来，实现更强泛化和更高层决策。

当前研究共识并不是“已经彻底解决了足式视觉导航”，而是：

**高层视觉导航能力、低层足式控制能力和系统级部署稳定性之间仍然存在明显鸿沟。**

## 2.3 视觉导航在足式机器人上的挑战和问题

足式机器人并不是把轮式导航代码直接换到底盘上就能稳定运行，其挑战主要体现在以下几个方面。

### 2.3.1 视觉感知的不稳定性

足式平台机身在运动过程中会出现周期性起伏和抖动，相机视角比轮式平台更不稳定。  
这会带来以下问题：

1. 连续帧的视差变化更大。
2. 动态模糊更明显。
3. 拓扑图匹配更容易出现偏差。
4. 相同目标在不同平台之间存在更大的 domain gap。

### 2.3.2 高层导航与低层步态控制之间的耦合

轮式平台中，高层输出的 `cmd_vel` 往往可以直接由底盘执行；  
而足式机器人中，高层导航输出必须先通过中间动作接口层，转换为低层步态控制器能够接受的参考量。

因此，足式机器人视觉导航的关键问题之一是：

**如何把“往哪里走”的高层决策稳定地翻译成“腿怎么动”或“轮足系统如何执行”的低层控制输入。**

### 2.3.3 安全性与稳定性问题

足式平台除了要考虑导航成功率，还必须考虑：

1. 是否会失稳。
2. 是否会在狭窄区域卡住。
3. 是否会因为急转、过大速度或曲率过高的路径导致跌倒。
4. 是否具备恢复和重规划机制。

因此，足式机器人上的视觉导航评估不能只看是否到达目标，还应关注恢复次数、稳定性边界和保守控制策略。

### 2.3.4 sim-to-real 与工程部署难题

足式机器人视觉导航常见的工程难题包括：

1. 仿真与真机图像差异大。
2. 相机外参和机身安装高度不同。
3. 传感器时间同步难。
4. 不同平台控制接口差异明显。
5. 实时推理频率受限。

这也是为什么本课题要把 MuJoCo 联合仿真和真机部署流程同时纳入研究主线。

## 2.4 相关领域的研究现状和发展趋势

### 2.4.1 扩散模型与扩散策略的发展

扩散模型最初主要用于生成任务，其核心思想是：  
通过逐步向真实数据添加噪声学习前向过程，再通过逆过程逐步去噪恢复目标数据。

经典工作 DDPM 奠定了扩散生成的基本框架，DDIM 则提出了更快的隐式采样方式。  
在机器人控制中，*Diffusion Policy* 将扩散生成思想引入动作建模，证明扩散过程不仅能生成图像，也能生成动作序列或轨迹序列。

这些工作对于本课题的意义在于：

1. 导航动作可以被视为条件生成问题。
2. 轨迹采样天然支持多模态输出。
3. 通过 DDIM 等采样策略可以进一步提升部署实时性。

相关论文链接：

1. Diffusion Policy: <https://arxiv.org/abs/2303.04137>  
2. DDIM: <https://arxiv.org/abs/2010.02502>  
3. Classifier-Free Guidance: <https://arxiv.org/abs/2207.12598>

### 2.4.2 视觉表示学习的发展趋势

视觉导航对特征表示质量非常敏感。  
从早期 CNN，到 ViT，再到 DINOv2 这类自监督视觉模型，视觉编码器的演进直接影响导航系统的泛化能力。

其中，DINOv2 的价值在于：

1. 更强的通用视觉特征。
2. 对视角变化、纹理变化和场景变化具有更强鲁棒性。
3. 更适合作为跨平台迁移的视觉编码基础。

论文链接：<https://arxiv.org/abs/2304.07193>

### 2.4.3 视觉导航与具身智能的发展趋势

近年来，视觉导航研究逐渐从“单任务导航器”发展为“统一具身代理”的组成部分。  
典型趋势包括：

1. 从纯视觉输入扩展到视觉、语言、本体感知、多传感器融合。
2. 从单一平台扩展到跨形态、跨任务迁移。
3. 从离线指标优化走向真实部署和长期自主运行。
4. 从局部最优策略走向大模型驱动的层次化决策。

相关综述与代表工作链接：

1. Robotics with Foundation Models Survey: <https://arxiv.org/abs/2402.02385>  
2. VLN Survey in the Era of Foundation Models: <https://arxiv.org/abs/2407.07035>  
3. CityWalker: <https://arxiv.org/abs/2411.17820>

### 2.4.4 对本课题的直接启发

对本课题而言，当前研究趋势至少给出三点直接启发：

1. 高层导航不一定要直接输出底层关节动作，输出中间路径点或中间动作表示更有利于跨平台迁移。
2. 扩散策略非常适合建模多模态导航轨迹，但必须处理实时性问题。
3. 更强的视觉编码器有望缓解 Lite3、Tron1 和轮式基线之间的视角与平台差异。

## 2.5 NoMaD 项目的原理和实现细节

### 2.5.1 NoMaD 的研究目标

NoMaD 的全称是 *Goal Masked Diffusion Policies for Navigation and Exploration*。  
其核心目标不是只做“目标导航”，也不是只做“无目标探索”，而是通过统一的条件扩散策略，在一个框架中同时学习两种能力。

论文链接：<https://arxiv.org/abs/2310.07896>  
项目页面：<https://general-navigation-models.github.io/nomad/>

### 2.5.2 NoMaD 的整体结构

NoMaD 在本仓库中的整体结构可以概括为：

```text
Observation Images + Goal Image
    -> Visual Encoder
    -> obsgoal_cond
    -> Distance Predictor + Diffusion Policy
    -> Sampled Trajectories
    -> Selected Waypoint
    -> PD Controller / Platform Bridge
```

这里还需要澄清一个在部署阶段很容易混淆的问题：实际运行时，机器人相机输入的确是真实世界中的当前图像，而 `topomap` 中的节点本质上也是提前采集并保存下来的真实环境图像。  
因此，NoMaD 不是先把视觉编码器输出“转换成一张拓扑图”，再在图上规划；更准确地说，拓扑节点本来就已经以图像记忆库的形式存在，视觉编码器负责把“当前观测图像 - 候选节点图像”这一对输入编码成条件向量，随后由距离预测网络完成局部定位，由扩散策略生成局部 waypoint 轨迹。  
换句话说，`topomap` 是外部提供的视觉锚点集合，编码器做的是匹配和条件化，而不是在线重建图结构。

与本课题直接相关的实现文件包括：

1. [nomad.py](../train/vint_train/models/nomad/nomad.py)
2. [nomad_vint.py](../train/vint_train/models/nomad/nomad_vint.py)
3. [train_utils.py](../train/vint_train/training/train_utils.py)
4. [navigate.py](../deployment/src/navigate.py)
5. [pd_controller.py](../deployment/src/pd_controller.py)

### 2.5.3 NoMaD 的三个核心子模块

#### 1. Visual Encoder

视觉编码器接收当前观测帧、历史帧和目标图像，输出统一条件向量 `obsgoal_cond`。  
在原始实现中，该模块主要基于 EfficientNet 和时序自注意力机制实现。

#### 2. Distance Predictor

距离预测网络根据 `obsgoal_cond` 估计当前观测与目标节点之间的距离，用于在 topomap 中选择最可能的局部子目标。

#### 3. Diffusion Policy

扩散策略不是一次性直接输出唯一动作，而是从随机噪声出发，在条件向量约束下逐步去噪，生成多条候选轨迹，再从中选出用于控制的局部 waypoint。

### 2.5.4 NoMaD 的训练流程

NoMaD 训练的关键步骤包括：

1. 从数据集中读取观测图像、目标图像和对应动作序列。
2. 对一部分样本随机遮蔽目标图像信息。
3. 通过视觉编码器得到条件表示。
4. 对真实动作序列加噪。
5. 训练噪声预测网络恢复噪声。
6. 同时训练距离预测网络。

从损失构成上看，NoMaD 的训练既包含扩散噪声预测损失，也包含目标距离预测损失。  
但从数值权重上看，扩散损失通常占主导地位，因此 NoMaD 的核心仍然是一个条件扩散策略。

## 2.6 NoMaD 系统中的 goal mask 机制

### 2.6.1 goal mask 的提出动机

传统目标导航方法通常默认机器人始终知道目标，而探索方法通常默认机器人没有明确目标。  
NoMaD 希望用同一个模型同时学习这两类行为，因此提出了 **goal mask** 机制。

它的基本思想是：

1. 当目标可见时，模型学习目标导向行为。
2. 当目标被遮蔽时，模型学习无目标探索行为。
3. 通过随机混合两类样本，让同一模型具备导航与探索的统一表示能力。

### 2.6.2 goal mask 在训练中的工作方式

在本仓库的训练实现中，`goal_mask_prob` 默认设置为 `0.5`。  
也就是说，在训练时，大约有一半样本会把目标 token 屏蔽掉。

对应实现位置：

1. [train/config/nomad.yaml](../train/config/nomad.yaml)
2. [train_utils.py](../train/vint_train/training/train_utils.py)
3. [nomad_vint.py](../train/vint_train/models/nomad/nomad_vint.py)

其机制可以概括为：

1. `mask = 0`  
   不遮蔽目标 token，模型能够利用目标图像信息，学习目标导航。

2. `mask = 1`  
   遮蔽目标 token，模型看不到目标图像，只能根据当前观测和历史运动模式学习探索行为。

在视觉编码器内部，这种 mask 不是简单把整张图像置零，而是通过自注意力中的 mask 机制禁止目标 token 参与有效信息融合。  
这使得同一套编码器可以在“有目标”和“无目标”两种模式之间切换。

如果从条件概率的角度理解，这一过程实际上对应两类学习目标：

1. `mask = 0` 时，模型学习的是 `p(a | o, g)`，即给定当前观测 `o` 和目标 `g` 时应该如何生成轨迹。
2. `mask = 1` 时，模型更接近于学习 `p(a | o)`，即在不给定目标的情况下，当前视觉场景下哪些未来轨迹是“合理且可通行”的。

这也解释了一个看似矛盾的问题：训练集里的每个样本明明都有“正确轨迹”，那么目标被遮蔽之后，模型到底学到了什么？  
答案是，模型并不是在学习一个“被隐藏但依然存在的秘密目标”，而是在利用数据集中真实的未来轨迹分布，学习当前场景下什么样的短时运动延伸最符合历史示范。  
例如，当机器人面前是走廊时，`mask = 1` 分支更容易学到沿走廊前进；当画面中存在开阔区域或路口时，它会学习若干可能的局部延伸方向。

因此，NoMaD 所谓的 exploration，并不是传统意义上基于全局地图的 frontier exploration，而更接近于一种由数据驱动的、面向局部可通行空间的探索先验。  
这也是为什么在训练实现中，距离预测损失主要只对 `mask = 0` 的样本有效，因为目标被遮蔽时，“当前距离某个显式目标还有多远”这一监督本身就不再稳定。

### 2.6.3 goal mask 在部署中的使用方式

NoMaD 在部署阶段对 goal mask 的使用非常直接：

#### 1. 导航模式

当需要机器人朝目标点或拓扑图节点前进时，设置：

`mask = 0`

此时：

1. 当前观测图像和目标图像共同进入视觉编码器。
2. 距离预测网络根据 `obsgoal_cond` 选择最接近的拓扑节点。
3. 扩散策略在有目标条件下生成轨迹。
4. 系统从多条候选轨迹中选出一个 waypoint，用于控制机器人前进。

在本仓库中，这一流程主要对应：

1. [navigate.py](../deployment/src/navigate.py)
2. [offline_inference.py](../scripts/analysis/offline_inference.py)
3. [nomad_mujoco_lite3_nav.py](../scripts/simulation/nomad_mujoco_lite3_nav.py)
4. [nomad_mujoco_lite3_state_machine.py](../scripts/simulation/nomad_mujoco_lite3_state_machine.py)

从工程系统角度看，更自然的做法不是把 NoMaD 只理解成一个“导航脚本”，而是把它封装成一个可切换模式的高层决策模块。  
一个较完整的部署状态机通常至少包含：

1. `idle`：等待任务或等待人工切换模式。
2. `navigate`：执行 `mask = 0` 的目标导航。
3. `explore`：执行 `mask = 1` 的无目标探索。
4. `recovery`：处理卡住、偏航、局部碰撞风险等异常。
5. `estop`：人工或安全逻辑触发的紧急停机。

这也说明，一个移动平台完全可以同时支持导航模式和探索模式，二者共享同一套 NoMaD 高层模型，只是在是否启用目标条件、是否接入 topomap、是否启用停止条件上存在差异。

对于本课题中的 Lite3 MuJoCo 实现，还可以进一步区分两种代码形态：

1. [nomad_mujoco_lite3_nav.py](../scripts/simulation/nomad_mujoco_lite3_nav.py)  
   已经完成了高层 NoMaD、中层 PD、底层 Lite3 locomotion 与 MuJoCo 物理的整合仿真，但主要采用单脚本组织方式。

2. [nomad_mujoco_lite3_state_machine.py](../scripts/simulation/nomad_mujoco_lite3_state_machine.py)  
   在保留原始整合逻辑的基础上，把高层接口、中层接口、底层接口和状态机分别拆开实现，更适合后续论文系统描述和真机迁移。

#### 2. 探索模式

当需要机器人在没有明确目标时执行探索，设置：

`mask = 1`

此时目标信息被遮蔽，模型输出更偏探索性的轨迹。  
在本仓库中，探索模式既体现在原始的 `deployment/src/explore.py`，也体现在 Lite3 MuJoCo 联合仿真脚本的 `explore` 模式中。

需要特别强调的是，部署时的探索模式并不是“把视野内所有空位都显式枚举一遍，再挑一个空位前进”。  
在实现上，系统通常会送入一个占位用的 `fake_goal`，同时设置 `mask = 1`，由于目标 token 在注意力中被屏蔽，真正起作用的是当前观测和历史上下文。  
扩散策略随后从 `p(a | o)` 这一分布中采样若干条短时 horizon 轨迹，这些轨迹反映的是“从当前画面出发，哪些运动延伸更像训练数据中出现过的可通行行为”。

这意味着：

1. 如果当前视野中只有一条明显通路，模型输出通常会集中到该方向。
2. 如果当前画面里存在多个可能通行方向，模型有机会采样出多条不同但合理的候选轨迹。
3. 如果某个区域虽然看起来空旷，但训练数据中很少出现朝该方向运动的示范，模型也未必会主动走过去。

因此，NoMaD 的探索模式本质上是局部的、反应式的、由数据分布塑形的探索，而不是显式几何建图意义上的“遍历所有可见空位”。

如果系统长时间一直停留在 `explore` 模式，并且没有额外的退出条件，那么平台确实会不断重新采样局部 waypoint，并持续移动。  
但这并不等于“完全随机乱走”：它通常会沿着模型认为更可通行、更符合训练分布的方向滚动前进。  
问题在于，若缺少约束，平台可能在局部区域来回摆动、重复绕圈，或者持续远离研究者原本想观察的区域。

因此，真正可部署的探索系统通常还需要加入：

1. 时间预算或里程预算。
2. 回环检测或重复区域检测。
3. 卡住检测与恢复逻辑。
4. 人工接管与紧急停车接口。
5. 当发现目标或收到新任务后切回导航模式的切换逻辑。

### 2.6.4 goal mask 与 topomap 导航的关系

在实际部署中，NoMaD 往往不是直接面对“唯一全局目标”，而是面对一个由多张目标节点图像组成的 topomap。  
系统会执行以下步骤：

1. 机器人在线采集当前真实观测图像。
2. 系统从预先构建好的 `topomap` 中取出当前搜索窗口内的若干候选节点图像。
3. 将“当前观测 - 候选节点”逐一组合编码，得到一组条件向量。
4. 在 `mask = 0` 条件下计算各候选节点与当前观测的距离。
5. 选择最近节点或下一个推进节点作为当前局部子目标。
6. 用该子目标对应的条件向量驱动扩散策略生成局部轨迹。

这里的关键点在于：NoMaD 不会先把视觉编码器结果重新组织成拓扑图，再在图上做一次显式规划。  
拓扑结构本身通常来自离线采集时的节点顺序、局部搜索窗口以及“closest node / next node”推进规则；视觉编码器负责的是视觉匹配和轨迹条件化。  
也正因为如此，部署阶段“真实图像”和“拓扑节点”之间并不矛盾，后者本身就是由真实图像构成的拓扑锚点。

候选节点图像的具体来源也需要区分清楚：

1. 在离线基线评测或数据集实验中，候选节点图像可以直接来自已有数据集轨迹，例如从 GoStanford 轨迹中按固定步长采样形成 `topomap`。
2. 在仿真或真实部署中，候选节点图像应来自当前环境本身，通常需要在部署前沿目标路线或目标区域预先采集，或者像 Lite3 MuJoCo 那样通过 `generate-topomap` 在当前场景中生成。

因此，`topomap` 候选节点既可能“来源于数据集”，也可能“来源于部署现场”，区别在于当前系统处在离线研究阶段还是实际部署阶段。  
但无论来源如何，它们都不是视觉编码器在线推理时临时生成的，而是提前准备好的视觉参考节点。

还需要进一步说明“多个目标”在部署中的两层含义：

1. 第一层是单次导航任务内部的多个拓扑节点。  
   这一点在当前仓库中其实已经实现。`navigate.py` 并不是只拿一个最终目标图像直接导航，而是维护 `closest node`、`goal node` 和局部搜索窗口，让多个节点按顺序充当局部视觉子目标。

2. 第二层是多个高层任务目标。  
   例如“先去 A 区域，再去 B 区域，最后去 C 区域”。这种能力在当前仓库中还没有被封装成完整任务管理器，但完全可以在 NoMaD 外围增加一个 `mission queue` 来实现：当前目标完成后，再加载下一个目标对应的 topomap 或目标节点集合。

这里要注意一个理论边界：距离预测网络的强项是在当前激活的候选节点集合内做局部子目标选择，而不是直接承担全局任务排序器的角色。  
因此，如果多个高层目标存在明确业务顺序，最好由上层任务管理器显式给出顺序；如果希望采用“最近目标优先”的自动调度，也应把它视为额外工程策略，而不是 NoMaD 原始框架天然保证的能力。

也就是说，goal mask 机制不仅是探索和导航模式切换的钥匙，也是 topomap 目标匹配和局部导航生成的前提。

### 2.6.5 goal mask 与 CFG 的关系

本课题进一步扩展了 NoMaD 的使用方式：  
既然 `mask = 0` 表示有条件分支，`mask = 1` 表示无条件分支，那么在部署时就可以借鉴生成模型中的 Classifier-Free Guidance 思想，构造：

1. 条件噪声预测分支 `eps_cond`
2. 无条件噪声预测分支 `eps_uncond`
3. 再通过 guidance scale 融合两者

这也是本课题在第四章中进行 CFG 引导实验的重要理论基础。

## 2.7 本章小结

本章围绕本课题所需的前置知识进行了系统梳理，主要结论如下：

1. 视觉导航的核心在于将视觉观测转化为可执行的局部决策，而 NoMaD 属于学习型视觉导航方法中的代表性工作。
2. 足式机器人视觉导航与轮式平台相比，最大的差别不只是机体形态，而是高层导航输出与低层控制系统之间存在更强耦合。
3. 扩散模型和扩散策略为导航提供了多模态轨迹生成能力，但需要通过 DDIM、CFG 等方式进一步满足部署实时性和可控性需求。
4. goal mask 是 NoMaD 最关键的机制之一，它使一个统一模型能够兼顾目标导航与无目标探索，并且为本课题中的 CFG 引导实验提供了直接理论基础。
5. 本课题后续对 Lite3 和 Tron1 的系统迁移，本质上是在 NoMaD 的高层导航能力基础上，重新设计中间桥接层和平台执行层，而不是从零重新定义导航问题。
