# 视觉导航与机器人形态（Morphology）关系研究

> 调研时间：2026年3月24日  
> 核心问题：视觉导航策略是否可以跨机器人形态（轮式 / 四足 / 双足）泛化？

---

## 1. 视觉导航能否跨机器人形态泛化？

### 1.1 核心结论：**有条件地可以**

关键在于**抽象层（Abstraction Layer）**的设计。现有研究表明：

| 抽象层类型 | 跨形态能力 | 代表项目 |
|-----------|-----------|---------|
| **归一化 waypoint (x,y)** | ✅ 强 | GNM, ViNT, NoMaD |
| **离散动作 (前进/左转/右转/停止)** | ✅ 强 | InternNav, NaVILA |
| **速度指令 (v, ω)** | ⚠️ 中等 | VP-Nav, NaVILA locomotion |
| **关节角度** | ❌ 弱，不可迁移 | 底层运动控制器专用 |

### 1.2 关键论文：GNM — 首个跨形态导航模型

**GNM: A General Navigation Model to Drive Any Robot**  
- 作者：Dhruv Shah, Ajay Sridhar, Arjun Bhorkar, Noriaki Hirose, Sergey Levine (UC Berkeley)
- 发表：ICRA 2023
- arXiv: https://arxiv.org/abs/2210.03370
- GitHub: https://github.com/PrieureDeSion/drive-any-robot
- 项目页: https://sites.google.com/view/drive-any-robot

**核心设计：**
1. **聚合异构数据集**：60小时导航轨迹，来自 **6种不同机器人平台**（不同尺寸、传感器、动力学）
2. **归一化动作空间**：将不同机器人的动作映射到统一的归一化空间 `(dx, dy)` —— 这是跨形态迁移的关键
3. **体态上下文（Embodiment Context）**：用时间上下文隐式编码机器人的能力
4. **零样本迁移**：GNM 在**未见过训练数据的四旋翼和 VizBot** 上成功部署

**关键发现：**
- 在多样数据上训练的全策略（omnipolicy）**优于**在任何单一数据集上训练的专家模型
- 对传感器放置扰动和物理退化（如轮胎卡住异物）具有鲁棒性

### 1.3 ViNT — 视觉导航基础模型

**ViNT: A Foundation Model for Visual Navigation**  
- 作者：Dhruv Shah, Ajay Sridhar, Nitish Dashora, Kyle Stachowicz, Kevin Black, Noriaki Hirose, Sergey Levine
- 发表：CoRL 2023 (Oral)
- arXiv: https://arxiv.org/abs/2306.14846
- 项目页: https://general-navigation-models.github.io/vint/

**关键特性：**
- **体态无关（Embodiment-agnostic）** 的动作预测：输出归一化的 `(x, y)` waypoint
- Transformer 架构，EfficientNet CNN 编码器
- 可通过 prompt-tuning 适配新任务（GPS waypoint、路由命令等）
- **正向迁移**：在多个导航数据集上训练，表现优于单数据集专家模型
- 可通过 diffusion 子目标提案探索新环境
- 成功解决**公里级导航**问题

### 1.4 NoMaD — 扩散策略导航

**NoMaD: Goal Masking Diffusion Policies for Navigation and Exploration**  
- 作者：Ajay Sridhar, Dhruv Shah, Catherine Glossop, Sergey Levine (UC Berkeley)
- 发表：ICRA 2024 **最佳论文奖**
- arXiv: https://arxiv.org/abs/2310.07896
- GitHub: https://github.com/robodhruv/visualnav-transformer

**关键设计：**
- 使用 ViNT 编码器 + Diffusion Model 解码器
- 统一的 diffusion 策略同时处理**目标导向导航**和**无目标探索**
- 输出：2D waypoint 轨迹 `(len_traj_pred, 2)` —— 仍然是形态无关的

**部署架构：**
```
视觉观测 → ViNT编码器 → Diffusion解码器 → (x,y) waypoint → PD控制器 → (v, ω) → 机器人底盘
```

## 2. 在腿足机器人上部署视觉导航的具体项目

### 2.1 NaVILA — 腿足机器人视觉-语言-动作模型 ⭐⭐⭐

**NaVILA: Legged Robot Vision-Language-Action Model for Navigation**
- 作者：An-Chieh Cheng, Yandong Ji, Zhaojing Yang 等 (UC San Diego, USC, NVIDIA)
- 发表：**RSS 2025**
- arXiv: https://arxiv.org/abs/2412.04453
- GitHub (VLA): https://github.com/AnjieCheng/NaVILA
- GitHub (运动控制): https://github.com/yang-zj1026/legged-loco
- 项目页: https://navila-bot.github.io/

**支持的机器人类型：**
| 机器人 | 类型 | 部署方式 |
|--------|------|---------|
| **Unitree Go2** | 四足 | ✅ 真实世界 + 仿真 (Isaac Sim) |
| **Unitree G1** | 双足人形 | ✅ 真实世界 |
| **Booster T1** | 双足人形 | ✅ 真实世界 |
| **Unitree H1** | 双足人形 | ✅ 仿真 (Isaac Sim) |

**两层架构（关键设计）：**
```
第一层：VLA 高层决策
    输入: 历史观测视频帧 + 自然语言任务指令
    输出: 自然语言动作命令（如 "move forward 50 cm", "turn left 30 degree", "stop"）
    模型: 基于 LLaMA-3 的 VLM，微调为 VLA

第二层：运动控制策略（Locomotion Policy）
    输入: 速度指令 (vx, vy, ω) 或离散动作
    输出: 关节力矩/角度
    特点: 端到端视觉运动策略，直接使用 LiDAR 训练，无需 teacher-student 蒸馏
```

**动作空间解析：**
- VLA 输出的是**自然语言**，解析为离散动作：
  - `stop` → 0
  - `move forward X cm` → 1（前进，X 可选 25/50/75 cm）
  - `turn left X degree` → 2（左转，X 可选 15/30/45 度）
  - `turn right X degree` → 3（右转，X 可选 15/30/45 度）
- 底层离散动作转换为速度指令发送给运动控制器

**数据特点：**
- 训练数据包括：R2R 室内导航、RxR、ScanQA、**YouTube 人类步行视频**、EnvDrop
- 从 **YouTube 人类第一人称步行视频** 学习导航策略（无需机器人数据！）

**核心贡献：**
> 1. NaVILA 是首个在**四足和双足人形机器人**上实现 VLN（Vision-Language Navigation）的系统
> 2. 视觉运动策略无需 teacher-student 蒸馏，直接从 LiDAR 交互学习
> 3. 引入 VLN-CE-Isaac 基准：基于物理仿真的低层机器人控制评估平台

### 2.2 InternNav — 多形态导航框架 ⭐⭐

**InternNav**
- 组织: InternRobotics (上海人工智能实验室)
- GitHub: https://github.com/InternRobotics/InternNav
- 比赛: IROS Challenge 2025 Nav Track

**支持的机器人类型：**
| 机器人 | 类型 | 控制器 |
|--------|------|--------|
| **Unitree H1** | 双足人形 | VlnMoveBySpeedController (RL运动策略) |
| **Agilex 轮式机器人** | 轮式 | DiscreteRobotController (cmd_vel) |
| 通用仿真机器人 | 多种 | VlnMoveByFlashController (传送式) |

**层次化控制架构：**
```
InternVLA (视觉-语言导航模型)
    ↓ 离散动作 (0=停止, 1=前进, 2=左转, 3=右转)
    ↓
控制器层 (三种模式)
    ├── FlashController: 直接设置位置（传送，仿真用）
    │     前进距离: 0.25m, 旋转角度: 15°
    ├── SpeedController (H1专用): RL运动策略
    │     输入: (forward_speed, lateral_speed, rotation_speed)
    │     内部: 使用关节位置跟踪 + IMU + 本体感受
    │     输出: 19自由度关节指令 (ArticulationAction)
    └── DiscreteRobotController (轮式): cmd_vel话题
          输入: Twist消息 (linear.x, angular.z)
```

**MPC 控制器（真实世界部署）：**
```python
# 真实世界部署使用 MPC + PID 控制器
# 导航模型输出 2D 轨迹 → MPC 跟踪 → (v, ω) 速度指令
class Mpc_controller:
    # 预测时域 N=20, 期望速度 0.3m/s
    # 动力学: dx = v*cos(θ), dy = v*sin(θ), dθ = ω
    # 输出: [v, ω] 线速度和角速度
```

**关键技术：**
- 使用 InternVLA-N1（基于 InternVL 的导航专用 VLA）
- Diffusion Policy 编码器用于动作预测
- 仿真中使用 InterNUtopia（基于 Isaac Sim 的仿真平台）
- 支持碰撞检测（VlnMoveByFlashCollisionController）

### 2.3 VP-Nav — 视觉+本体感受导航 ⭐⭐

**Coupling Vision and Proprioception for Navigation of Legged Robots**
- 作者：Zipeng Fu, Ashish Kumar, Ananye Agarwal, Haozhi Qi, Jitendra Malik, Deepak Pathak
- 单位：Carnegie Mellon University, UC Berkeley
- 发表：**CVPR 2022**（Best Paper Award at Multimodal Learning Workshop）
- arXiv: https://arxiv.org/abs/2112.02094
- GitHub: https://github.com/MarkFzp/navigation-locomotion
- 项目页: https://navigation-locomotion.github.io/

**机器人：Unitree A1 四足机器人**

**层次化架构：**
```
高层: 视觉导航
    输入: 深度图像 → 占用地图 → 代价地图
    规划: Fast Marching Planner → 目标路径
    输出: 速度指令 (vx, vy, ω)

中层: 安全顾问 (Safety Advisor)
    碰撞检测器: 本体感受 → 检测玻璃墙、未预期障碍
    跌倒预测器: 预测不稳定地形上的跌倒概率 → 降低速度
    将检测到的障碍添加到占用地图

低层: RL 运动控制策略
    输入: 速度指令 + 本体感受
    输出: 关节力矩
    基于 RMA (Rapid Motor Adaptation) 框架
```

**核心创新：本体感受（Proprioception）**
- 解决了**纯视觉不足**的问题：玻璃墙（不可见）、暗光环境、地形滑度/柔软度
- 碰撞检测器：通过本体感受信号检测意外碰撞
- 跌倒预测器：在不稳定地面上降低速度指令
- 室外部署：30米目标导航，穿越水坑、草地，抵抗 2kg 质量块冲击

### 2.4 CityWalker — 城市导航 ⭐

**CityWalker: Learning Embodied Urban Navigation from Web-Scale Videos**
- 作者：Xinhao Liu, Jintong Li 等 (NYU ai4ce Lab)
- 发表：**CVPR 2025**
- arXiv: https://arxiv.org/abs/2411.17820
- GitHub: https://github.com/ai4ce/CityWalker
- 项目页: https://ai4ce.github.io/CityWalker/

**当前形态支持：**
- ❌ **不直接支持四足/双足**
- 主要面向城市自主导航智能体（使用第一人称步行/驾驶视频训练）
- 数据来源：**数千小时的在线城市步行和驾驶视频**
- 使用 DPVO 获取里程计

**动作空间：**
- 输出：2D waypoint 轨迹预测 `(B, len_traj_pred, 2)` —— 欧几里得或极坐标表示
- 解码器：支持 Attention 和 **Diffusion Policy** 两种模式
- 到达预测：预测是否到达目标

**与 ViNT/NoMaD 的关系：**
- README 致谢中明确引用了 ViNT 和 NoMaD
- 架构思想相似：视觉编码器(DINOv2/EfficientNet/ResNet) + waypoint 预测器

**可迁移性评估：**
- 输出的 waypoint 本身是形态无关的
- 理论上可以接入腿足机器人的速度指令层
- 提供了 **TeleopDataset** 和微调 (fine_tune.py) 接口，支持在机器人遥操作数据上微调

## 3. 关键技术问题：如何处理运动层？

### 3.1 分层控制架构总结

所有在腿足机器人上成功部署视觉导航的项目都采用了**分层架构**：

```
┌─────────────────────────────────────────────────┐
│           高层：视觉导航策略                       │
│  (形态无关 / Morphology-Agnostic)                │
│  输入: 视觉图像 + 目标                            │
│  输出: waypoint (x,y) / 离散动作 / 语言指令       │
├─────────────────────────────────────────────────┤
│           中层：运动规划 / 速度指令                 │
│  (部分形态相关)                                   │
│  输入: waypoint / 离散动作                        │
│  输出: 速度指令 (vx, vy, ω)                       │
│  实现: PD控制器 / MPC / 离散到连续映射             │
├─────────────────────────────────────────────────┤
│           低层：运动控制策略                       │
│  (完全形态相关 / Morphology-Specific)             │
│  输入: 速度指令 + 本体感受                        │
│  输出: 关节力矩/角度                              │
│  实现: RL运动策略 (每个机器人专用)                 │
└─────────────────────────────────────────────────┘
```

### 3.2 各项目运动层对比

| 项目 | 高层输出 | 中层转换 | 低层控制器 | 形态无关？ |
|------|---------|---------|-----------|-----------|
| **ViNT/NoMaD** | waypoint (x,y) | PD Controller → (v,ω) | 轮式底盘直接执行 | ✅ 高层完全无关 |
| **NaVILA** | 语言动作命令 | 解析为离散动作 | RL locomotion policy (Go2/G1/H1专用) | ✅ VLA层完全无关 |
| **InternNav** | 离散动作(0/1/2/3) | 动作到速度映射 | FlashController / SpeedController(H1) | ✅ 导航模型无关 |
| **VP-Nav** | 速度指令(v,ω) | 安全顾问调整 | RMA-based locomotion (A1专用) | ⚠️ 导航层部分无关 |
| **CityWalker** | waypoint 轨迹 | (未部署在机器人) | N/A | ✅ 理论上无关 |
| **GNM** | 归一化 waypoint | 反归一化 + PD | 各平台原生驱动 | ✅ 核心创新 |

### 3.3 运动策略独立性的关键

> **核心洞察：** 导航策略和运动策略可以**完全解耦**。导航策略只需要输出"去哪里"（WHERE），运动策略负责"怎么去"（HOW）。

**解耦接口的三种范式：**

1. **Waypoint 接口** (GNM/ViNT/NoMaD/CityWalker)
   ```
   导航策略 → (x, y) waypoint → [PD控制器 / MPC] → (v, ω) → 运动策略
   ```
   - 最灵活，任何能跟踪 waypoint 的机器人都可使用
   - 需要 PD/MPC 中间层将 waypoint 转换为速度指令

2. **离散动作接口** (NaVILA/InternNav)
   ```
   导航策略 → {前进/左转/右转/停止} → 运动控制器 → 关节指令
   ```
   - 最简单，跨形态最容易实现
   - 粒度较粗，不适合精细导航

3. **速度指令接口** (VP-Nav)
   ```
   导航策略 → (vx, vy, ω) → 运动策略 → 关节指令
   ```
   - 最直接，但需要运动策略能跟踪任意速度指令
   - 四足/双足都可实现速度跟踪

## 4. 特定主题深入分析

### 4.1 "形态无关导航" (Morphology-Agnostic Navigation)

**最直接的证据来自 GNM 系列：**
- GNM 在 **6种不同机器人**上训练，包括不同大小的轮式机器人
- 部署在**未见过的四旋翼**上成功导航 → 跨越了轮式→空中的鸿沟
- 关键设计决策：**归一化动作空间** + **时间上下文编码体态**

**ViNT 进一步验证：**
- ViNT 网站明确描述架构为 "embodiment-agnostic"
- 通过归一化动作预测，消除了对具体机器人动力学的依赖

### 4.2 "跨体态导航迁移" (Cross-Embodiment Navigation Transfer)

| 迁移方向 | 证据 | 项目 |
|---------|------|------|
| 轮式 → 轮式（不同型号） | ✅ 强 | GNM (6种机器人) |
| 轮式 → 四旋翼 | ✅ 实验验证 | GNM |
| 轮式数据 → 四足部署 | ⚠️ 间接 | NaVILA (YouTube视频训练) |
| 人类视频 → 四足/双足 | ✅ 实验验证 | NaVILA (YouTube Human Touring) |
| 仿真 → 真实世界 | ✅ 实验验证 | NaVILA, VP-Nav |

## 5. 腿足 vs 轮式机器人部署的意义

### 5.1 腿足机器人的优势

| 维度 | 轮式机器人 | 腿足机器人 | 参考项目 |
|------|-----------|-----------|---------|
| **地形通过性** | 仅平坦地面 | 草地、碎石、不平地面 | VP-Nav (水坑、草地) |
| **楼梯通行** | ❌ 无法通行 | ✅ 可上下楼 | NaVILA (G1, H1) |
| **障碍跨越** | ❌ 需绕行 | ✅ 可跨越小障碍 | VP-Nav |
| **户外导航** | ⚠️ 受限 | ✅ 全地形 | VP-Nav (30m户外导航) |
| **动态环境** | ⚠️ 稳定性差 | ✅ 可恢复碰撞 | VP-Nav (2kg冲击恢复) |
| **狭窄空间** | ⚠️ 转弯半径限制 | ✅ 原地转弯 | InternNav (H1) |

### 5.2 真实世界部署挑战

**NaVILA 的真实世界发现：**
- 视觉运动策略（Vision-based locomotion）比盲运动策略（Blind locomotion）在成功率上显著更高
- 原因：视觉策略能更有效地避障（如透明表面）
- 挑战：Sim-to-Real Gap（通过直接 LiDAR 交互训练减小）

**VP-Nav 的真实世界发现：**
- 纯视觉导航在以下场景失败：
  - 玻璃门/墙（深度相机无法检测）
  - 暗光环境（树木不可见）
  - 突然出现的人类障碍（FoV外）
- 本体感受解决了以上所有问题

**InternNav (IROS Challenge) 的约束：**
- 公平比赛要求：固定机器人 USD 模型、控制器和观测空间
- 控制器：4个离散动作（前进0.25m，左转15°，右转15°，停止）
- 观测：自我中心单目 RGB-D

### 5.3 关键洞察

> **从轮式到腿足的迁移本质上是一个"How to Walk"问题，而不是"Where to Walk"问题。**

- "Where to Walk"（去哪里）= 视觉导航策略 → **可以跨形态共享**
- "How to Walk"（怎么走）= 运动控制策略 → **必须形态专用**

> 因此，**waypoint 抽象层是实现跨形态迁移的关键接口**。只要运动控制器能跟踪 waypoint/速度指令，任何导航模型都可以在腿足机器人上使用。

## 6. 对本项目（基于 ViNT/NoMaD 的四足部署）的启示

### 6.1 技术路线建议

```
方案A: 直接适配 NoMaD
    NoMaD waypoint → PD/MPC控制器 → (v, ω) → Unitree Go1/Go2 locomotion policy

方案B: 参考 NaVILA 架构
    VLA/NoMaD → 离散动作 → 离散到速度映射 → locomotion policy

方案C: 参考 VP-Nav 架构
    视觉导航 → 速度指令 → 安全顾问 → locomotion policy + 本体感受
```

### 6.2 需要解决的关键问题

1. **运动策略获取**：需要 Go1/Go2 的 RL locomotion policy（推荐参考 `legged-loco`）
2. **Waypoint → 速度指令转换**：NoMaD 已有 `pd_controller.py`，可直接复用
3. **相机高度差异**：GNM 已证明对传感器放置变化具有鲁棒性
4. **本体感受整合**：VP-Nav 证明对腿足导航至关重要
5. **地形感知**：NaVILA 的视觉运动策略值得参考
