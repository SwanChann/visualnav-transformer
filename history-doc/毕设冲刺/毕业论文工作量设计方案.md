**以 NoMaD 为统一高层视觉导航策略，围绕轮式基线、Lite3 四足 MuJoCo 联合导航、Tron1 双轮足 MuJoCo 迁移，以及 Lite3/Tron1 真机部署四个层次，完成一条从算法复现、部署优化到跨形态落地验证的完整研究链。**

1. 你已经不只是“有 Lite3 初步接口”，而是有了 [nomad_mujoco_lite3_nav.py](../scripts/nomad_mujoco_lite3_nav.py) 这种可以独立支撑一节主体工作的联合仿真代码。

3. 把 Tron1 和真机部署纳入主线后，论文会从“单一平台优化”升级为“多形态部署研究”，研究价值和答辩说服力都会更强。

## 5. 多平台统一架构建议

## 5.1 建议的统一系统分层

```text
Perception Layer
  -> RGB observation / goal image / topomap image

High-Level Navigation Layer
  -> NoMaD / DDIM / CFG / DINOv2
  -> output sampled trajectories and selected waypoint

Command Bridge Layer
  -> waypoint selection
  -> waypoint to platform command
  -> safety clipping / recovery / mode switching

Platform Execution Layer
  -> Wheeled robot: cmd_vel
  -> Lite3: velocity command -> locomotion policy -> joint control
  -> Tron1: wheel-legged command -> platform controller

Evaluation Layer
  -> success rate / latency / trajectory deviation / recovery count / deployment readiness
```

## 5.2 轮式、四足、双轮足三类平台差异

| 维度 | 轮式平台 | Lite3 四足 | Tron1 双轮足 |
|---|---|---|---|
| 高层输出 | `waypoint` / `cmd_vel` | `waypoint` / `velocity` | `waypoint` / `wheel-leg command` |
| 中间桥接层复杂度 | 低 | 高 | 高 |
| 相机视角稳定性 | 较高 | 中等，存在步态起伏 | 中等，轮足复合动态 |
| 低层执行 | 底盘直接执行 | locomotion policy + joint control | 轮足控制器 |
| 主要风险 | 打滑、障碍绕行 | 失稳、卡住、跌倒 | 模式切换、姿态约束 |

## 5.3 为什么 NoMaD 适合做多平台迁移

这部分建议保留并进一步强化：

1. NoMaD 输出的是相对路径点，不是关节动作。
2. 这使得高层导航可以与平台低层执行解耦。
3. 因而同一 NoMaD 高层有机会复用到轮式、四足、双轮足平台。
4. 真正需要变化的是中间桥接层，而不是整个导航策略重写。

## 7. 最终创新点建议重写

本轮之后，创新点不能再只写“足式迁移”。

建议最终归纳为四点：

1. **针对 NoMaD 构建面向多形态机器人部署的统一高层导航框架。**

3. **提出 NoMaD 向 Tron1 双轮足平台迁移的桥接方案。**  
   重点解决 `waypoint -> wheel-legged command` 的接口抽象问题。

4. **构建 Lite3 与 Tron1 真机部署流程。**  
   让论文从“算法和仿真研究”走向“部署流程与工程落地研究”。
