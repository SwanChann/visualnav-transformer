### 4.6 同地图多目标点导航

这一轮已经不再推荐“手工拆分 topomap 子目录”的旧方法。
现在采用的方案是：

1. 固定一张 MuJoCo 地图。
2. 在地图可通行区域内随机采样若干个 `goal point`。
3. 在 MuJoCo 里把这些目标点可视化成 marker。
4. 在每个目标点位置采集 `goal vision`。
5. 对每个目标点在线生成从当前位姿到该点的 topomap 段。
6. 按顺序执行 `Goal A -> Goal B -> Goal C`。

这样更符合 NoMaD 的闭环机制，也保证当前观测、goal vision、topomap 都来自同一个 MuJoCo 场景域。

#### 状态机入口：随机三目标点

```bash
python scripts/simulation/nomad_mujoco_lite3_state_machine.py \
  --mode navigate --map hard \
  --scheduler ddim --ddim-steps 2 \
  --goal-source random_points --num-goals 3 \
  --topomap-nodes 20 --max-steps 300
```

#### 导航主机入口：完整任务编排

```bash
python scripts/deployment/nomad_navigation_host.py \
  --backend mujoco --save-plan --continue-on-failure \
  --plan-file scripts/configs/navigation_host/lite3_navigation_host_plan.json
```

对应计划文件会依次执行：

1. `stand`
2. `navigate`（`goal_source=random_points`，`num_goals=3`）
3. `explore`
4. `estop`

#### 最新验证结果（2026-04-13）

| 入口 | 结果文件 | 步数 | 路径距离 | 到达目标 |
|---|---|---:|---:|---|
| 导航主机 `navigate` 三目标点 | `results/nomad_mujoco/20260413_203128_lite3_mujoco_navigation_host_navigate/summary.txt` | 38 | 4.052 m | ✅ True |
| 导航主机整机编排摘要 | `results/deployment/20260413_203128_lite3_mujoco_navigation_host/host_summary.md` | 4 任务 | 全部成功 | ✅ success |

主机日志中只出现一次 MuJoCo 模型加载和一次 GUI viewer 启动，说明任务切换时没有重载地图、没有关闭窗口，机器人位姿也是连续承接的。

### 4.7 Capture 队列与 goal vision 选择

在运行导航主机时：

1. 按 `c` 保存当前相机图像到 capture 队列。
2. 按 `[` / `]` 切换当前选中的 capture。
3. 当前选中的 capture 会作为界面上的 `goal vision` 预览。
4. 后续任务如果使用 `--goal-source capture_queue`，会从共享 session 中读取所选图像和位姿作为导航目标。
5. 按 `e` 或 `Esc` 可触发急停。

#### 交互式 capture 队列计划

```bash
python scripts/deployment/nomad_navigation_host.py \
  --backend mujoco \
  --plan-file scripts/configs/navigation_host/lite3_navigation_host_capture_plan.json
```

该计划会先执行 `stand` 和 `explore`，方便你在主机窗口中按 `c` 采图；随后进入 `navigate + goal_source=capture_queue`，从队列中读取 goal vision。

## 5. 导航主机（Navigation Host）

导航主机是状态机之上的任务编排层，支持 MuJoCo / Real 两种后端，支持 dry-run 预验证和 JSON 计划文件。

### 5.1 MuJoCo 后端 — dry-run

```bash
python scripts/deployment/nomad_navigation_host.py \
  --backend mujoco --dry-run --save-plan \
  --plan-file scripts/configs/navigation_host/lite3_navigation_host_plan.json
```

### 5.2 MuJoCo 后端 — 实际运行

```bash
python scripts/deployment/nomad_navigation_host.py \
  --backend mujoco --save-plan --continue-on-failure \
  --plan-file scripts/configs/navigation_host/lite3_navigation_host_plan.json
```

### 5.3 Real 后端 — dry-run

真机后端需要指定桥接模块和类名。dry-run 模式仅验证参数合法性，不启动实际导航。

```bash
python scripts/deployment/nomad_navigation_host.py \
  --backend real --dry-run \
  --bridge-module lite3_bridge_stub --bridge-class Lite3BridgeStub \
  --plan-file scripts/configs/navigation_host/lite3_navigation_host_plan.json
```

说明：如果计划文件里包含 `goal_source=random_points`，`real` 后端会主动拒绝，这是正确行为，因为随机目标点和在线仿真目标可视化只属于 MuJoCo。

### 5.4 JSON 计划文件模式

可以通过 JSON 文件批量定义多个任务。当前仓库已经内置两份推荐计划：

```bash
# 自动化验证计划：stand -> navigate(随机三目标点) -> explore -> estop
python scripts/deployment/nomad_navigation_host.py \
  --backend mujoco --save-plan --continue-on-failure \
  --plan-file scripts/configs/navigation_host/lite3_navigation_host_plan.json

# 交互式 capture 队列计划：stand -> explore(期间按 c 采图) -> navigate(capture_queue) -> estop
python scripts/deployment/nomad_navigation_host.py \
  --backend mujoco \
  --plan-file scripts/configs/navigation_host/lite3_navigation_host_capture_plan.json
```

## 7. 推理配置参考

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--scheduler` | `ddpm` | 扩散调度器，可选 `ddpm` / `ddim` |
| `--ddim-steps` | `10` | DDIM 步数，推荐 `2`（4.84× 加速） |
| `--cfg-weight` | `0.0` | Classifier-Free Guidance 权重，`0.0` = 关闭 |
| `--waypoint` | `2` | 选择扩散轨迹第几个路径点（0~7） |
| `--max-steps` | `200` | 最大 NoMaD 决策步数 |
| `--close-threshold` | `3.0` | 到达目标判定距离（米） |
| `--policy-config` | (默认) | 自定义策略配置路径 |
| `--policy-checkpoint` | (默认) | 自定义检查点路径 |

### 最优推理配置（阶段二实验结论）

```
--scheduler ddim --ddim-steps 2 --cfg-weight 0.0
```

- 综合分数：5.6477
- 推理延迟：6.18ms（原始 DDPM 的 4.84× 加速）
- 导航成功率：3/3 地图全部成功
